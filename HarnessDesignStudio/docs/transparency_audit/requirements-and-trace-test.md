## Definition of done

Test (a) trace any number in under a minute; (b) change any assumption/constant/margin/rule without editing code; (c) reproduce a colleague's result from an exported file; (d) explain it in a design review without "the tool computed it".

| Test | Verdict | SYS | EE | AIT |
|---|---|---|---|---|
| **(a)** under one minute | **FAIL** | Fails for connector choice, pin choice (#7, #8); passes for "which harness and why" (#6, 8 min, not 1). | Fails: gauge/drop need config + code (#1: 12-20 min; #2: 25 min). | Fails: cut length, labels, BOM metres are not traced at all (#3, #4, #13), but "Ready to build" and test-limit source are quick (#14 4 min, #15 5 min). |
| **(b)** change any assumption without editing code | **PARTIAL** | Segmentation mode, naming, EMC class pairs, grounding concept: yes. Selection of connector/pin strategy, method choice: no. | Ampacity, derating, resistivity, drop limit, service loop: yes. The 2-conductor round trip, bundle-size definition, K-lookup rule, wire-part-vs-gauge coupling: no. | Test limits, strip/contacts: yes. Label format, cut order, blocking set of "Ready to build", cut allowance: no. |
| **(c)** reproduce a colleague's result from an exported file | **PARTIAL** | Yes only with the **project folder** (`model_hash` equality, `verify --outputs`). The export alone (`export.json`, CSV, xlsx) lacks config values and cannot be loaded. | Same; config appears only as a 16-hex hash (`provenance.json`), so the ampacity table of a colleague is unknowable from the export. | An AIT person can rebuild from the xlsx itself (it holds all it needs) and sees version+hash in footer; cannot check it against the design. |
| **(d)** explain without "the tool computed it" | **PARTIAL** | Segmentation and standard-based rules: yes (requirement IDs, ECSS clause). | Gauge ampacity+drop: answerable only after reading code (equation, round trip, bundle). "Why 0.6 bundle?" - only the user's own number, not the tool's. | Cut length and labels: "because the tool sums segments and adds a loop" is the best answer today. |

Where the answer differs by persona: (a) is worst for EE because the equations are code-only; (b) is worst for AIT because output layout and readiness logic are not configurable; (c) is worst for EE because the config values behind derating are not in the export; (d) is best for SYS (requirement-driven rules).
