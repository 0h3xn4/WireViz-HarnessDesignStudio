This release gives you more to choose and more to read. Three more parts of the method are now models you can pick (how pins are fitted on a connector, which connector the tool uses for an interface, and what a label says), `explain` now shows how the gauge of a wire was chosen, and the as-built records can be held to a tolerance and, if you want, required before a release. The editor can write the open data from its Export window, and the diagram is a little calmer to work with. The calculations, the 39 design rules and the numbers are as in 1.14.0 unless you choose another setting.

### The main changes

- **Three more models you can choose.** Each is a setting with today's method as its default, so nothing changes until you pick another. *Pin fit strategy:* the first free run of pins from pin 1 up (the default), from the last pin down, or with a free pin between interfaces where there is room. *Connector choice:* the first free connector that carries the type (the default), or the one with the fewest or the most pins left over. *Label format:* the text the tool always printed (the default), a compact one, a descriptive one, or your own templates. `explain` says which model is in force. How the interfaces share a harness was already selectable (`segmentation.mode`); the audit text now says so. The keys are on `docs/models/selectable-models.md`.
- **`explain` shows how a gauge was chosen.** For a wire it lists the gauges the search tried, from the smallest conductor up, the current each can carry after derating, the voltage drop from there on, and the first that fits, with the settings and assumptions it used. It runs the same search that `generate` runs, so it cannot disagree with the wire. `explain` also ends with the page of the documentation that describes the model behind each number, and the Explain window and the Why tab of the editor show that line too.
- **Two more built-in assumptions are settings.** The bill of materials can add spare contacts and an allowance on the wire (both 0 by default, so the quantities are the ones you always got). Three design rules that named no assumption now name one.
- **As-built tolerances (optional, off by default).** With a tolerance set for cut or strip lengths, the as-built report marks a recorded length *out of limit* or *within limit* instead of just *differs from design*.
- **A release gate on the as-built records (optional, off by default).** When you switch it on, `release` stops while a harness has no as-built records, a needed value is missing, or a length is out of tolerance. `release --accept-asbuilt REASON` releases anyway and writes the reason into the change log.
- **In the editor.** The Export window has a check box to include the open data (JSON and CSV of every result). You can drag the vertical piece of the line an interface takes between two devices, with Undo. Quick mode no longer shows the automatic check progress or the *N pending* chips. The file `diagram/marks.json` no longer keeps marks of a connection or interface you deleted.

### Upgrading

There is no migration: the file format keeps its schema version (1) and a project from 1.14.0 opens as it is. There is no new project file. The new settings are optional keys in files a project may already have (`config/model.json`, `config/generation.json` and `config/naming.json`) and all of them default to what the tool did before. The files the tool writes for the packaged examples are the same as in 1.14.0, apart from the tool version in the stamp and the model hash that follows from it. If you choose a new pin fit strategy or connector choice, the harness plans become out of date and generating again places the pins anew.

### Known limits

- **Nobody looked at the program on a real display.** The window was tested with Qt's offscreen platform (texts, widgets, states and renderings), not by a person at a screen.
- **Two things were not done, because they need engineering input:** an AC or skin-effect model of the voltage drop (the drop models are DC), and a mass model that counts splices and backshells.
- **Smaller limits.** The choice of a connector acts when the tool picks one, not on a connector you picked yourself. The release window shows the as-built blocker but has no field for the reason of `--accept-asbuilt` (use the command line), and a release does not freeze the as-built records.
- **No compliance and no sign-off is claimed.** The owner has not signed this release off. The packages are not signed (Windows SmartScreen shows *Windows protected your PC*: **More info**, then **Run anyway**), the configuration values are placeholders and the parts are example parts.
