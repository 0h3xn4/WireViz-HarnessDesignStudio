- **The Systems engineer path, from a blank project to a connection list, is in the screens.** *Add device* can make the first connector with the device. *Link connectors* can add a connector for a device that has none, pairs pins by pin number or from a table you paste (**Pair by pin number**, **Paste a pairing…**), shows the proposal with what was left out and waits for **Accept the pairs**. The *Next step* page shows the first open problem as a card (what is wrong, what to do, **Show it**, **Waive…** where the check allows it, **Approve…** for an unapproved part), and a warning no longer holds it on *Fix what is marked*. The Systems engineer role stays on the Next step page or the diagram after each step, its menus leave out the engineering entries (they are still in the command palette, Ctrl+K), and the Devices tab shows and edits the role of each pin.
- **A connection list as output.** A project with connections now writes `system/connections.csv` and `system/connections.xlsx` in the style of an interface control document: for each pair of pins the device, connector, pin, signal and role at both ends, the interface type, the harness made from it and a note. The connections are on the block diagram and in `traceability.csv`. `export` and the Outputs area work for a project that has connections and no harness. A project without connections writes none of this.
- **A direction on a pin, and the transmit/receive words are a setting.** A pin can say `in`, `out` or `bidirectional`; where it is set the connection review uses it before any name (so analog, discrete, LVDS, pyro and I2C clock pins are checked too) and `import-pinout` / `export-pinout` carry a *Direction* column. The word pairs (`TX`/`RX`, `MOSI`/`MISO` ...) are the key `signal_counterparts` of `config/naming.json`; until you set it the old table is used.
- **Two people who both press Generate can merge.** A new project gets a `.gitattributes` that keeps `generated/generation.json` free of conflict markers, and the new command `merge-fix DIR` keeps your version of that record, runs `generate` and `check`, and refuses (changing nothing) when any other file is in conflict. The manual says which files still conflict by design.
- **Different people in a release, if you want it.** The setting `release_distinct_roles` (`config DIR --distinct-roles on`) asks for three different people as author, checker and releaser, a sensible date, and takes the name from Git when none is given. Off by default; then nothing changes.
- **A release freezes the device pins that its wires end on.** `import-pinout --replace` used to change such pins after the release and exit 0; now it is refused, and `check` reports a change made behind the tool.
- **Far less waiting in big projects.** An edit, the autosave and an undo step cost a fraction of what they did on a project of 200 devices (an edit to a wire 43 ms to 2.5 ms; the autosave no longer stops the window; an undo step holds the change, not a second copy of the harness), the export builds one cell style instead of tens of thousands, and making a harness from 1,000 connection pairs takes about 0.1 s instead of 31.7 s. The results are the same as in 1.8.1 (tests compare them with a copy of the 1.8.1 code).
- **One current limit for a wire.** The rules `bundle-current` and `current-over-wire` took different limits for the same wire when a temperature factor was set (2.5 A against 1.25 A); both use one function now. Both rule ids stay.
- **A shorter README.** The README starts with a 10-minute tour whose commands a test runs; the release history moved to `docs/STATUS.md`.
- **For people who install from source:** the tool needs **Python 3.14 or newer**. The packages bring their own Python, so nothing changes for the `.deb`, the `.tar.gz` and the Windows files.
- **Unchanged for existing work.** No change of the file format (every new field is left out of the files while it is empty), the design rules stay 39, and the files and outputs of a project without connections are byte-identical to 1.8.1 apart from the tool version they record (checked file by file).
- **Not in this release / for you to know.** Not built: coax and twisted-pair shield ends, requirement IDs in the outputs, sharding `links.json` (two people who each add a connection still conflict), per-harness incremental export, buses, variants, import of existing wire lists and command-line versions of the 1.8.0 editing features. Nobody has watched the screens on a real display, and the owner has not signed this release off. The packages are not signed.
