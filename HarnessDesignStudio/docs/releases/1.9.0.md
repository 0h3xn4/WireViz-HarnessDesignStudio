This release lets the Systems engineer go from a blank project to a connection list, helps teams who share a project in Git, and makes big projects much faster. No file-format change: existing projects open as they are.

### Systems engineer: from blank project to connection list

- **Add a device together with its first connector.**
- **Link connectors is faster to use.** Add a missing connector on the spot, pair pins by pin number, or paste a two-column pairing. The proposal is always shown first, and nothing is paired until you press **Accept the pairs**.
- **The Next step page shows the first open problem as a card:** what is wrong, what to do, and buttons for **Show it**, **Waive…** (where the check allows it) and **Approve…** (for an unapproved part). A warning no longer holds you on *Fix what is marked*.
- **Less on screen for this role.** You stay on the Next step page or the diagram after each step. Engineering menu entries moved to the command palette (Ctrl+K), and the Devices tab shows and edits each pin's role.

### A connection list as output

- A project with connections now writes `system/connections.csv` and `system/connections.xlsx`, in the style of an interface control document: for each pair of pins, the device, connector, pin, signal and role at both ends, plus the interface type and a note.
- Connections appear on the block diagram and in `traceability.csv`.
- `export` and the Outputs area work for a project that has connections but no harness yet.

### Pin direction and signal pairing

- A pin can now say `in`, `out` or `bidirectional`. Where it is set, the connection review uses it before looking at names, so analog, discrete, LVDS, pyro and I2C clock pins are checked too. `import-pinout` and `export-pinout` carry a *Direction* column.
- The word pairs used to pair pins (`TX`/`RX`, `MOSI`/`MISO`, …) are now a project setting, `signal_counterparts` in `config/naming.json`. Until you set it, the old table is used.

### Working as a team

- **Two people who both press Generate can merge.** New projects get a `.gitattributes` that keeps `generated/generation.json` free of conflict markers. The new command `merge-fix DIR` keeps your version of that file, runs `generate` and `check`, and refuses (changing nothing) if any other file is in conflict.
- **Optional: three different people in a release.** Switch on `release_distinct_roles` (`config DIR --distinct-roles on`) to require a different author, checker and releaser, a sensible date, and the name from Git when none is given. Off by default.

### Improvements

- **Much faster on big projects.** On a project of 200 devices, an edit to one wire went from 43 ms to 2.5 ms, the autosave no longer freezes the window, and an undo step holds only the change. Making a harness from 1,000 connection pairs went from 31.7 s to about 0.1 s. Results are identical to 1.8.1.
- **A shorter README** that starts with a 10-minute tour. The release history moved to `docs/STATUS.md`.

### Fixes

- **A release now freezes the device pins its wires end on.** `import-pinout --replace` used to change such pins after a release and report success; it is now refused, and `check` reports a change made behind the tool.
- **One current limit per wire.** `bundle-current` and `current-over-wire` gave different limits for the same wire when a temperature factor was set (2.5 A against 1.25 A). Both now use the same calculation; the rule IDs are unchanged.

### Upgrading

- **Installing from source needs Python 3.14 or newer.** The packages bring their own Python, so nothing changes for the `.deb`, the `.tar.gz` and the Windows files.
- The file format is unchanged and the design rules stay at 39. For a project without connections, every generated file is identical to 1.8.1 apart from the tool version it records.

### Not in this release

- Coax and twisted-pair shield ends, requirement IDs in the outputs, and sharding `links.json` (two people who each add a connection still conflict).
- Buses, variants, import of existing wire lists, and command-line versions of the 1.8.0 editing features.
