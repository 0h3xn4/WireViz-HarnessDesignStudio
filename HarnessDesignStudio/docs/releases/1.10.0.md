- **The outer conductor of a coax is bonded at both ends.** Generation gave every shield group the two ends of the project's grounding concept, so a coax got one end floating, or both while the concept was a placeholder. A coax now always gets a 360-degree backshell bond at both ends, whatever the concept says; a coax you group yourself gets the same. Twisted pairs, shielded pairs, quads and overall shields still follow the concept. The shield checks read the new ends: a coax that was reported only because of the concept is no longer reported, and a coax you set to floating still is. In the shipped examples only `flatsat` has a coax (harness W005). Regenerating a project that has a coax changes that group in a harness that is not released; a released harness is frozen and does not change. A coax group that was generated cannot have its ends set by hand; if your practice needs another end, tell the owner.
- **A cable pin shows what it carries.** In the pinout tables of the harnesses (`pinouts.csv`, and the workbook of each harness that shows them) the Signal and Interface cells of a cable pin were empty unless the pin had a signal of its own. A pin without one now shows the signal and the interface of the wires that end on it (several different values sorted and joined with `;`). A pin with its own value keeps it, a spare pin stays empty, and the pinouts of the device (box) connectors are unchanged.
- **The requirement ID is in the wire list and the traceability matrix.** While any interface has a requirement ID, `wirelist.csv` gets a Requirement column after EMC class and `traceability.csv` one after Routed. A project with no requirement ID keeps both tables as they were.
- **The program no longer aborts when it ends while the autosave is being written.** Since 1.9.0 the autosave journal is written by a background thread; a script, a test or any other exit without closing the window could end with `QThread: Destroyed while thread '' is still running` when the writer was slow. Ending the program now waits for the autosave writer and for a running design check (at most five seconds each). Closing the window was not affected.
- **For developers.** `CLAUDE.md` is split into a short core file and six area notes in `docs/developer/agent/`.
- **Unchanged for existing work.** No change of the file format, the design rules stay 39. Of the files the four shipped examples write, only the pinout tables, the per-harness workbooks and the files of `flatsat` differ from 1.9.0, apart from the tool version they record. The comparison with the files of release 1.2.0 that earlier releases used could not stay (the coax change alters the model hash of `flatsat`); the tool compares with a stored baseline that is renewed on purpose (`docs/ui/OUTPUT_HASHES_BASELINE.json`, D-183, D-184).
- **Not in this release / for you to know.** Still open: the owner's decisions on the standards and quality process, variants, the licence and signing, a sharded `links.json`, pair-part counts and the waiver `finding_hash`. Nobody has signed this release off as the owner, and the packages are not signed.
