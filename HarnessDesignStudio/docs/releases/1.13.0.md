This is a small follow-up to the transparency release (1.12.0). It closes three gaps that the audit of 1.12.0 left open: the numbers in `system/export.json` have their units, the settings files can explain themselves, and a test that touches a wire you changed by hand says so. The calculations, the 39 design rules and the numbers are as in 1.12.0.

The file format keeps its schema version (1) and there is no migration. One written file changes on purpose: `system/export.json` gets one more object, `field_units` (see below). Of the files of the four packaged examples and the eleven checked scenarios, only that file differs from 1.12.0, apart from the tool version in the stamp and the model hash that follows from it.

### 1. Units in `system/export.json`

- The file has a new top-level object `field_units` that maps the path of each numeric field to its unit, for example `"harnesses[].wires[].length_m": "m"`, `"interfaces[].max_current_a": "A"`, `"parts[].mass_per_m_g": "g/m"` and `"harnesses[].wires[].gauge_awg": "AWG"` (the gauge stays the plain AWG number in the file). A count or a flag has `none` and what it is.
- Nothing is renamed or moved and `format_version` stays 1, so a program that reads the file and does not know the object is not affected. The key `units` still holds the devices, which is why the new object is called `field_units`.
- The table behind it is in one place in the code and is held by a test against the fields of the model and against the numbers of real files. The output check reports a number that has no unit; a file from before this change is still accepted.

### 2. Comments in the settings files (opt-in)

- A file in `config/` can now carry the reserved key `_about`: for every setting its label, unit, range, source, what it does, where it is used, its default and the assumption behind it, copied from the registry of the tool. `harness-design-studio settings DIR --annotate` writes or refreshes it, `--no-annotate` takes it out, and `new --annotate-config` starts a new project with it. It is off unless you ask for it.
- It is a comment, not a setting: loading ignores it, `settings --set` refuses it, and it is not part of the model hash or of any written output, so annotating a project makes nothing out of date. A project without it opens and saves as before.
- `validate` and `config` warn when an entry no longer matches what the tool says now (a warning only; `--annotate` fixes it). The tooltip of a value on the engineering values page now also shows the range and the source.

### 3. Overrides and deviations on the tests

- For a harness in which a test is about a wire with an override or a recorded deviation, `tests.csv` has a last column `Deviations` (`override gauge_awg: reason; deviation current-over-wire: reason`), the *Tests* sheet of the build workbook starts with the band *Overrides and deviations* and has the same column, and the as-built report repeats the mark on the line of a measured test. A project with neither writes the same bytes as before.

### What is not in this release

- The comments in the settings files are not on by default, a save does not refresh a stale entry by itself, and there is no place for notes of your own per key.
- The other open decisions of `docs/transparency_final_audit.md` are still open. The standards and quality process, variants and a sharded `links.json`, and the soldering questions for the AIT engineers stay open too (`docs/OPEN_DECISIONS.md`).

### The honest limits

- **Nobody looked at the program on a real display.** The editor was tested with Qt's offscreen platform: texts, widgets and states, not what a person sees.
- **No compliance and no sign-off is claimed.** The owner has not signed this release off and this page is not a statement of compliance.
- **The packages are not signed.** Windows SmartScreen shows *Windows protected your PC* (**More info**, then **Run anyway**).
- **The example values are placeholders** for learning, not engineering data.
- **The tests were written by the author of the code.** CI runs the whole suite on Linux and Windows; an independent review by a person is still to come.
