# M1 demo note

**Done** (all in `src/harness_design_studio/core`, headless)
- Strict, immutable model for both layers (unit, interface type/instance, connector, pin, wire, shield group, splice, branch point, segment, harness, part), with ID rules, AWG/mm² helpers.
- Project folder format with canonical JSON, per-subsystem and per-harness files (`docs/FILE_FORMAT.md`), deterministic `model_hash`.
- Referential-integrity checker: 24 negative cases, each with a test.
- Load with recovery mode (quarantine, no silent drops, no data values in messages), merge-conflict detection, duplicate-key and NaN rejection, newer-version read-only, in-memory migration v0 to v1 with backup-on-save.
- Atomic saves with `.bak`, plain-language disk errors, long-path handling for Windows, same-project-twice lock, on-disk change detection.
- Transactions with undo/redo; a change that would break consistency is rolled back.
- Starter parts and 16 interface types (example data, no numbers), default config with placeholders (`docs/PLACEHOLDERS.md`), reference project `mini3` with a committed golden copy.
- CLI: `harness validate`, `harness check` (adds Git-merge checks), `harness migrate`.

**Tested**: 156 tests pass, 1 skipped (read-only folder test needs a non-root user; this container runs as root). Core coverage 97.6% (gate 90% now enforced). Fuzz (hypothesis: byte corruption, random JSON, random value mutation of valid files) and a seeded soak test (3 x 1,500 random edits/undo/redo/save/reload with integrity and hash checks). Both were checked to fail when the loader or the rollback is deliberately broken. Bugs the tests found and I fixed: trailing newline accepted in IDs, `socket` import for host name in the offline test, same-process lock treated as stale.

**Stress size** (200 units, 2,000 interfaces, 150 harnesses, 19,950 wires, `python -m tools.bench_stress`): load 0.23 s, full save 0.26 s, unchanged save 0.10 s, integrity 0.03 s, one transaction 0.06 s.

**Open / risks**
- A transaction costs about 60 ms at stress size because integrity is re-checked for the whole project twice; that is inside the 100 ms budget but with little room. Make it incremental in M3.
- Windows-only code paths (`\\?\` long paths, process liveness check via ctypes) are untested here; the Windows CI job must run them. Cross-file saves are not atomic as a set (see FILE_FORMAT.md, Saving).
- The CLI is not yet in the frozen package (only the GUI is packaged); do that when the GUI uses the core (M2).
- Imports (CSV/XLSX, library, CAD lengths) and their fuzz tests are M2/M5. DRC rules beyond referential integrity are M4.
- Decisions to confirm: connector IDs and wire IDs are globally unique (D-50), IDs unique ignoring case (D-51).
