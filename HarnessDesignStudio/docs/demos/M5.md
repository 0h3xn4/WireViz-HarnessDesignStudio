# M5 demo note: outputs

**Done**
- **Harness drawing** (SVG per A3 sheet, PDF A3 and A4, multi-sheet) with title block, shields, segments, spare pins, continued headings; black and grey only.
- **Tables** per harness: wire list, pinouts, BOM, mass and length, continuity and isolation tests, labels; **system**: BOM, mass and length totals, mating matrix, traceability matrix, box pinouts, DRC findings and report.
- **System diagrams**: block diagram (interfaces by category) and harness overview (nominal solid, redundant dashed), SVG and PDF.
- **Exports**: XLSX per harness and for the system, WireViz-style YAML per harness, one documented JSON file (`docs/OUTPUTS.md`).
- **Stamps** on every file (generator version and model hash), a **manifest** with sha256 per file, and **stale detection**: quick in the editor (up to date / out of date / not exported), deep in `harness verify DIR --outputs` (also finds edited and missing files).
- **Verifier v2**: re-reads the files and compares them with the design without using the builders (23 error codes, each exercised by a mutation test). Export is refused if it fails.
- **CLI**: `harness export DIR`, `harness verify DIR --outputs`. **Editor**: Harness plans tab shows output status and an Export button (worker thread, progress, Cancel, independent check before writing).
- **Third reference project**: `sat15_full` (sat15 with clearly labelled EXAMPLE numbers: gauges, lengths, masses, test limits) so every output has content.
- **Along the way**: the packaged-app self-test now also generates, exports and verifies; `xml.sax.saxutils` was replaced because it breaks the offline guarantee; XLSX is written deterministically (fixed zip and document timestamps).

**Tested**: 459 tests pass (1 skipped: needs a non-root user). New: determinism on 3 projects, verifier clean on all three, mutation tests for every verifier check, golden digests for every output file of three reference projects plus reviewable mini3 text goldens, PDF opens in a real reader (poppler) with correct page sizes, pagination, greyscale and contrast checks, manifest/stale/modified, foreign files kept, CLI, 7 GUI tests. Core coverage 95%. Ruff, mypy strict clean; packaged app self-test passes.

**Performance** (stress project: 2,000 interfaces, 140 harnesses, 20,000 wires): build about 28 s, independent check about 10 s, output about 106 MB in 2,500 files. There is no target for this in the plan; the editor runs it in a worker with progress and Cancel. The big costs are per-harness XLSX and PDF/SVG writing.

**Placeholders in use**: undecided gauges print "pending", unknown lengths and masses are listed as missing, test limits read "TBD (placeholder)", date, author, checker and approver show "-". Title block field list (D-15) and D-11 (derating numbers) still need the owner.

**UX targets**: export is two clicks (Harness plans tab, Export); status is visible without clicking. Not yet reviewed with screenshots or users; open: no preview of drawings inside the editor (open the SVG or PDF), the Harness plans tab is dense at small window sizes.

**Limits and risks**
- Drawings are wire-by-wire diagrams, not a geometric layout of branches; segments are listed, not drawn.
- WireViz YAML has not been validated against the WireViz program.
- PDF text is Courier only; characters outside Windows-1252 print as "?".
- The system block diagram uses zone lanes, not the positions from the editor, and gets crowded above about 60 units.
- Windows and Rocky 8 builds are still untested.
