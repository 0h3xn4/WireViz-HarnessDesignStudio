# M4 demo note: design rule check

**Done**
- **20 rules** (`core/drc/`): duplicate IDs, dangling wires, model consistency, unassigned signals, floating pins, mating halves (gender, mating part, pin count, keying), signal directions, contact current, wire current, voltage drop, spare pins, shield termination and grounding end, nominal/redundant mixing, pyro mixing, category separation, EMC class mixing, look-alike connectors, unapproved parts, and "checks not run". Verifier mismatches (interfaces against wires) appear as errors too. Every finding says what, why and how to fix; one-click fix where it is safe (regenerate harnesses for unassigned signals and verifier mismatches).
- **Honesty about placeholders**: rules that need numbers nobody entered check nothing and the "not checked" notes say so; the report header lists the placeholder configuration.
- **Waivers**: warnings only, justification of at least 10 characters, saved in `waivers.json`, applied immediately, listed in the report with their justification; waivers whose finding disappeared are listed too.
- **Report and CLI**: `harness drc DIR` prints the Markdown report (deterministic, golden-tested for `sat15`), exit code 1 on unwaived errors.
- **Editor**: Problems panel shows logical and design rule findings together with a "checking / all N rules checked" line; Show selects the unit or interface or opens the harness; Fix and Waive as before; tab badge and to-do list include them. The check runs in a background thread on a cheap copy, 1.2 s after the last edit.
- **Fixes along the way**: `GenerationPlan.empty` ignored pin-only changes; `mini3` hand-made harness had 2-pin cable connectors on 3-pin box connectors (the new mating rule caught it; data corrected).

**Tested**: 415 tests pass (1 skipped: needs a non-root user): 20 rules x (fires + stays quiet), a test that fails when a rule has no positive case, fix, waiver (persistence, errors refused, stale), report golden, CLI, stress-size timing, and 8 GUI tests. Core coverage 94% (gate 90%). Ruff and mypy strict clean.

**Performance** (stress project, 2,000 interfaces, 20,000 wires): full check 0.8 s. Edits stay at the M2 level (rename 90–110 ms, move 95–105 ms, undo/redo 120–190 ms) because the check waits for a pause. Measured honestly: running the check *while* editing doubles edit time (Python threads share one interpreter lock), so the 300 ms delay I first tried was too short and was changed to 1.2 s. **Open:** the acceptance wording asks for incremental DRC; this is background-after-pause, not incremental. Making rules incremental per object, or running the check in a separate process, would remove the slowdown during an in-flight check.

**Placeholders in use**: derating, grounding concept, spare pins, category and EMC separation, so about half the electrical rules report "not checked" on the sample projects. D-11 (real numbers) is still needed from the owner before a clean report means anything. Test-only numbers are used in tests and never shipped.

**UX targets**: findings read as sentences with Show, Fix and Waive; no screenshot review of the new Problems states yet (do it with `python -m tools.gui_screenshots` before the next UX gate). Open: 24 "connectors chosen by the tool" notes crowd the panel on `sat15`; a "confirm all" fix would help (M7).

**Limits and risks**
- Multi-drop interfaces are still skipped by generation and therefore by DRC.
- The EMC rule's configuration format (`conflicting_class_pairs`) is my choice; the owner or EMC engineer may want another.
- Look-alike connectors warns for every unit with several identical connectors in use, which is true for the starter parts (no keying data); expect waivers or real keying data.
- Windows and Rocky 8 builds are untested here.
