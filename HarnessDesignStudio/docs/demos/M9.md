# M9 demo note: release hardening (release candidate 0.1.0rc3)

**Done**
- **Fuzzing** (`tests/test_fuzz.py`, long run with `HARNESS_FUZZ_EXAMPLES=5000`): random corruptions of every project file (wrong types, deleted keys, duplicated items, huge values, truncated or flipped bytes, 50,000-level nesting), then the whole chain: load, integrity, rules, verifier, generation, outputs, output verifier. Also CSV and XLSX importers, damaged outputs and manifests. It found **five real crashes**, all fixed with regression tests: CSV with bare carriage returns (old Mac files) or odd characters; a damaged interface-type file stopping generation; damaged output files (for example a broken zip) stopping the output verifier; connectors of one unit with mixed keying stopping a rule; a harness without connectors stopping the drawing sketch. A 3,000-example run per target (about 5 minutes) is now clean.
- **Security review** (`docs/SECURITY.md`, `tests/test_security.py`): symlinked project files are ignored and never read; files over 64 MB are refused; `.xlsx` zip bombs, millions of empty rows and 16,000 columns are refused (tested with a crafted bomb); hostile names (`<script>`, `=HYPERLINK`, `../..`, right-to-left marks, backticks) are harmless in SVG, CSV, XLSX and YAML and the output verifier still passes; a manifest that lists `../victim.txt` or `/etc/hostname` cannot make the tool delete anything; damaged journals are ignored; an AST scan fails the test suite if code uses eval, exec, pickle, subprocess, os.system, ctypes, sockets or network modules. The Windows-only ctypes branch was removed (Ubuntu only).
- **Ready for the data you will supply**: `harness config DIR` (checklist of the 17 engineering values: what is missing, what depends on it; invalid values such as a factor above 1 or an ampacity table that falls with thicker wire are rejected with a reason and are also an unwaivable rule error `config-invalid`); `--ampacity-csv` loads the current-by-gauge table; `harness import-parts` (approved parts list; you say what each approval value means, unknown values are errors, never guessed); `harness import-lengths` (millimetres by default, decimal commas accepted). `docs/IMPORTS.md`, with the KiCad note.
- **Options for D-10 and D-15** written up in `docs/OPEN_DECISIONS.md`; D-120 to D-122 recorded.
- **Release**: Ubuntu 22.04 build image and a clean-machine test script (`packaging/ubuntu/container/`), `README.md`, release checklist updated, `tools/release_check` now includes fuzzing and security.

**Tested**: 614 tests pass (1 skipped: needs a non-root user), core coverage 96.6%. The release checklist passed every step on this machine except one test that I had not yet extended for the new rule (fixed; full suite re-run clean).
