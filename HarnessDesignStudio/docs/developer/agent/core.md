# Core, generation, rules, wires, connections, library, KiCad import: notes for agents

These sections were moved word for word from [`CLAUDE.md`](../../../CLAUDE.md) on 2026-10-29 (decision D-182); only this introduction is new. Read them when you work in `src/harness_design_studio/core/` (the model, the file layout, generation, the design rules, wire and connector editing, connections, the library, the KiCad import).

## Core layout (M1)
`core/model` (immutable strict models), `core/integrity.py`, `core/commands.py` (History: transactions, undo/redo), `core/io` (layout, loader, saver, migrate, fs), `core/starter.py`, `core/samples.py` (`mini3`). Format: `docs/FILE_FORMAT.md`; placeholders: `docs/PLACEHOLDERS.md`.
- Edit model objects only with `evolve()` and `History.execute`; never mutate `Project` directly outside commands/loader.
- Regenerate the golden fixture only on purpose: `python -c "from harness_design_studio.core.samples import mini3; from harness_design_studio.core.io.saver import save_project; save_project(mini3(), 'tests/fixtures/projects/mini3')"` and review the diff.
- Tests that run as root skip the read-only folder test; run the suite as a normal user in CI.

## Generation layout (M3)
`core/generate/` (`segmentation`, `wiring`, `pins`, `sizing`, `lengths`, `mass`, `naming`, `explain`, `engine`), `core/verify.py` (independent verifier), `core/model/generation.py` (record with provenance). `plan_generation(project)` is pure and returns ops + `RegenReport` + record; the GUI previews it (`GeneratePreviewDialog`), runs it in `PlanWorker` and applies it through `History`.
- Never put timestamps or history wording into provenance: a second plan must be empty and byte-identical.
- Verifier must stay independent of the generator: do not import wiring/pin logic into `core/verify.py`.
- Goldens: `tests/fixtures/projects/mini3` (written by `save_project(mini3())`, see the M1 section) and `sat15` (generated). Regenerate sat15 on purpose: `python -c "from harness_design_studio.core.samples import sat15; from harness_design_studio.core.generate.engine import generate_project; from harness_design_studio.core.io.saver import save_project; p=sat15(); generate_project(p); save_project(p,'tests/fixtures/projects/sat15')"` (delete the folder first) and review the diff.
- Text-replace patches fail silently after `ruff format`; grep to confirm they applied.

## Design rule check layout (M4)
`core/drc/` (`base` Rule/Hit, `rules` RULES registry, `report` Markdown report, `__init__` run/fix_ops/locate). Add a rule: write a check generator, register it in `RULES`, add a positive case to `POSITIVE` in `tests/test_drc.py` (a test fails if a rule has none) and make sure it stays quiet on the clean project. Rules needing numbers must stay silent while config is `null` and be listed in `_unchecked`.
- `checks.find` stays the fast synchronous logical layer; the controller merges it with background DRC results (`DrcWorker` waits for the helper process, 1.2 s after the last edit; waivers applied at display time).
- The check runs in a helper process (`gui/drc_process.py`, `core/drc/worker.py`, D-128; a thread held the GIL and stalled edits). Do not add synchronous DRC calls to edit paths. The packaged program must route `--drc-worker` first (`packaging/gui_entry.py`; `--selftest` checks it). Keep the pieces small: one pickle call holds the sender's GIL.
- Regenerate the sat15 DRC report golden on purpose: `python -m harness_design_studio.cli.main drc tests/fixtures/projects/sat15 > tests/fixtures/drc/sat15.md`.

## Incremental work (release 1.9, R3)
- `History.execute` asks `core/integrity.IntegrityTracker` (the errors of `check_integrity`, found again only where the project differs from the last look). A new integrity check that reads something new must say so in `_Reads` (what its result depends on) and, if it can only warn, is not tracked; `tests/test_integrity_tracker.py` compares the tracker with the verbatim 1.8.1 check (`tests/reference/integrity_181.py`) on random edits, and a scenario there per thing a check reads.
- `core/io/layout.serialize` remembers each file's bytes by the identity of the (immutable) objects it is made from; never mutate an entity or its lists in place. The journal (`core/recovery.journal_bytes`) is written by `gui/controller.JournalWorker` in a thread from a copy of the project; anything that clears the journal calls `ctl.stop_journal()` first. `model.base.evolve` keeps the objects of the fields it does not change. `outputs/buildsheet._cell` makes one cell style per combination and workbook.

## Editing wires (1.4.0 M1)
`core/wires.py` (`plan_wire_edit`, `plan_wire_reset`, `find_wire`, `wire_part_choices`: gauge, type, colour, length lock the wire; `Wire.label` and `Wire.note` are always kept by generation, which also reports a labelled wire it cannot carry over), `gui/wire_editor.py` (`WireEditor`, the *Edit wire* tab of `HarnessView`, in a scroll area so it never shrinks the drawing). Wire list columns Label and Note exist only when a wire has one (`tables.uses_wire_text`), and `outputs/verify.py` checks them. `Wire.manual` and `ShieldGroup.manual` mark what a person drew or grouped (`plan_add_wire`, `plan_delete_wires`, `plan_group_wires`, `plan_ungroup_all`); generation keeps them (`_wire_keys` leaves them out, `_shields` reserves their IDs) and the verifier warns (`pin_shared`) instead of failing when a drawn wire shares a pin; the design rule `pin-shared` (the 35th rule; 39 rules since the connection rules of D-173). `Pin.function`, `Connector.label` and `Harness.label` (D-163): `devices` edits the function and the box label, `wires.plan_set_labels` the harness and cable labels, the pinout tables add `Function` and `Termination` columns only when used (`tables.uses_pin_function`, `uses_termination`, and the same in `verify.py`). `core/vcs/gitinfo.py` (D-164) reads the last commit of the repository around the project folder from the `.git` files (never starts `git`; keep it that way, `tests/test_security.py` forbids `subprocess`); the Revisions panel shows it. Plan: `docs/ait/AIT_FEEDBACK_PLAN.md`; `core/device_library.py` (D-165): a device library file (export, merge, read, `plan_device_import` that only adds and renames a taken ID), the Devices tab buttons, `export-devices`/`import-devices`; the parts import reads `.tsv`/`.json` and InvenTree column names (`imports.parse_json_table`, `library_import._category_word`). Decisions D-160 to D-165. `core/manual_harness.py` (D-166, after 1.4.0): a harness a person makes with no interface (`plan_new_harness`, `plan_add_connector`, `plan_set_pin`, `plan_delete_connector`; `Harness.generated` stays False so Generate leaves it, and a harness Generate made refuses a connector), `gui/connector_editor.py` (the Connectors tab) and `HarnessView.newHarnessRequested` / `MainWindow.new_harness_flow` (Ctrl+Shift+H). Since 1.6.0 (D-168) the empty diagram of a project without units has the button **Add a device** (`canvas.py`, `strings.EMPTY_ADD_DEVICE`; the same as Edit > Add unit > Device…, Ctrl+Shift+N), and no text on the start screens names a control that does not exist.

## Connections (D-173, since 1.8.0)
`core/links.py` (no Qt): `propose_pairs(project, a_connector, b_connector)` pairs the pins of two device connectors by signal name only (equal names and the TX/RX-type counterparts, counterparts first, never by position, output to output and input to input not paired, a pin used once, pins another link pairs left out; returns a `Proposal` with `pairs`, `unpaired_a`, `unpaired_b`, `notes`); the planners `plan_add_link`, `plan_set_pairs`, `plan_rename_link`, `plan_delete_link`, `plan_set_roles` (pure, one undo step, a released harness's link refuses with the reason) and `plan_create_harness` (a harness with `generated=False`, cable connectors from `manual_harness`, one `manual` wire for each pair from `wires.plan_add_wire`, `harness_id` on the link; no length, gauge or colour); `derived_interfaces` (what a link carries, for display only, never stored), `effective_role`, `check_link`/`check_links` (the review, codes `link_dangling`, `link_pin_reused`, `link_direction_conflict`, `link_signal_mismatch`, `link_pin_unpaired`, `link_power_without_return`), `link_caption`. Model: `Link` and `PinPair` (`core/model/logical.py`), `Project.links`, `Pin.role` (power, return, ground, signal, shield, spare; empty means derived); file `logical/links.json` only while a link exists; integrity `dangling_link`, `link_pin_missing`, `link_pin_reused`, `link_same_device`; design rules `link-unpaired`, `link-direction`, `link-signal-mismatch`, `link-power-return` (39 rules; the DRC report says *Rules run: 39*; `output_hashes` maps 39 to 34). Screens: `gui/link_dialog.py` (`LinkDialog`: the window Link connectors, Edit > Link connectors…, Ctrl+Shift+K, the Connect tool and C after two devices; `CreateHarnessDialog`, `harness_preview`), `gui/canvas_links.py` (the connection lines and the derived interface under the connector names), the **Connections** group of `project_tree.py`, Edit > Selected connection, Design > Check my connections (the Connections filter of `problems_panel.py`), and the Next step key `make_harness`; the interface-type Connect stays under Edit > Connect with an interface type…. **Rules:** the tool never creates a harness unprompted (only the button Create harness, after a preview, `tests/test_ui_links.py` checks it); the person's pinout is the source of truth and Generate keeps it; a field added for links is optional and left out while empty, so files stay byte-identical while no link exists (`tests/test_links_files.py`, `python -m tools.output_hashes --check docs/ui/OUTPUT_HASHES_BASELINE.json`); a link of a released harness is locked with it. User page: `docs/user-manual/connect-two-connectors.md`; pictures `docs/img/link-connectors-window.png` and `connections-diagram.png` (`tools/tab_screenshots.py`, `_connection_pictures`).

Since 1.9.0 (W3): `Pin.direction` (sparse `in`/`out`/`bidir`, empty = not set; `devices.parse_pin_direction`; the sparse `Direction` column of the pinout tables and its mirror in `outputs/verify.py`; read by `pinout_import`) decides `link_direction_conflict` and the proposal before the interface types and the name guess; the counterpart words are `config/naming.json` `signal_counterparts` (`core/counterparts.py`, validated in `configcheck.validate_counterparts`, set by `configcheck.plan_set_counterparts` and `config --counterparts`; default table `DEFAULT_COUNTERPARTS` when unset); `plan_create_harness`, `propose_pairs` and `check_links` run in one pass (`link_pin_index`, `wires.plan_add_wires`, `_NameIndex`) and `tests/test_links_same_as_181.py` compares them with `tests/reference/links_181.py`, a verbatim copy of the 1.8.1 module (do not edit it); `tests/test_links_scaling.py` guards the scaling.

## Harness and connector editing (D-174, since 1.8.0)
`core/connector_edit.py` (no Qt): `plan_edit_connector` (part, gender, keying, name), `plan_edit_pin` (signal, role, function, termination, contact size; the contact only on a harness a person made), `plan_add_pins`, `plan_rename_pin` (wires follow), `plan_delete_pin`, `plan_reset_connector`; pure, one undo step, a released harness refuses with the reason. **A generated harness's connectors are edited through a lock, not refused**: the sparse field `Connector.locked` (omitted while false) marks a cable connector a person edited, and `generate/engine.py` `_keep_edited_connector` keeps its part, gender, keying and pin details while the pin IDs, their number and each pin's contact still follow the device; `_warn_lost_data` names an edited connector it cannot keep (`locked_data_lost`); the lock is the whole connector, `plan_reset_connector` gives it back. `core/wires.py`: `plan_regroup`, `plan_set_group_ends` (groups a person made only; those of the interface type refuse), `plan_bulk_wire_edit`, `bulk_targets`, `signals_of`, `wires_changed` (`plan_wire_edit` for many wires in one `Put`, so the wires are locked exactly like an edited wire). `core/links.py`: `link_ends` and `link_path` (display only). Screens: `gui/connector_editor.py` (Edit connector, pin Signal and Role, Pin ID with Add/Rename/Delete, *Give back to Generate*), `gui/harness_edit_dialogs.py` (`BulkWireDialog`, `ChangeGroupDialog`: they only plan and offer `ops()`; the editors run them through `run_dialog`, which the window sets), `gui/wire_editor.py` (*Change group…*, *Edit all wires…*), Edit > Edit all wires of the harness… (Ctrl+Shift+B, `act-bulk-wires`), `gui/canvas_links.py` (the connector boxes at the ends, drawn only in Expert mode or with View > Show connectors on connections, `act-connection-ends`, setting `ui/connection_ends`, box `settings-connection-ends`; the tooltip's Path), *Show the harness* (`act-link-show-harness`, the tree row, the right-click menu of a connection line, which M2 left empty because the actions were not in `view.menu_actions`). **Rules:** every new field optional and omitted while unused (`python -m tools.output_hashes --check docs/ui/OUTPUT_HASHES_BASELINE.json` stays *identical*, no golden changes); the window screens say *device*; a window shows a mistake in a line and keeps its button off. Tests: `tests/test_connector_edit.py`, `test_group_edit.py`, `test_bulk_wire_edit.py`, `test_link_ends.py` (no Qt) and `test_ui_connector_edit.py`, `test_ui_group_bulk_edit.py`, `test_ui_connection_ends.py`. User pages: `docs/user-manual/build-a-harness-by-hand.md` (Change a connector and its pins), `edit-a-wire.md` (sections 9, 10), `connect-two-connectors.md`.

## Library layout (D-175, since 1.8.0)
`core/subsystem_library.py` (no Qt): a subsystem is a set of devices with the links between them in one file `harness-subsystem-library` (version 1; schema in `docs/FILE_FORMAT.md`); `export_subsystem`, `read_subsystem`/`write_subsystem`, `plan_subsystem_import` (devices through `device_library.plan_device_import`, so a taken ID is renamed and nothing is overwritten; `Unit.subsystem` set to the name; connections through `links.plan_add_link` on the new connectors via `DeviceRow.connector_ids`; all or nothing; one undo step; `with_placements` puts them in one lane). `core/library_folder.py`: the library folder (`scan_folder` never raises and reads only; `load_entry`, `describe_entry`; `save_devices`, `save_subsystem` are the only writers and never replace a subsystem file). `core/copies.py`: a number of the same device (`plan_copies`, `device_count`, `copy_ids`: `ID`, `ID-R`, `ID-3` ...; built on `edit.ops_redundant_copy(suffix=...)`; nothing stored). Screens: `gui/library_window.py` (`LibraryWindow`, non-modal top-level window over the shared controller, `SaveToLibraryDialog`; reads the folder with `JobRunner`; own size and place under `library/`), `MainWindow.library_folder`/`set_library_folder`/`open_library_flow`/`choose_library_folder_flow` (File > Library…, Ctrl+Shift+O; Ctrl+Shift+L is Arrange; File > Library folder…; the setting `library/folder` is per person), the Settings > Project row, the Home page button, `ctl.add_device(count=)` and `ctl.make_copies`, the number field of the Add device window and the Devices tab. **Rules:** the tool stays offline (a shared library is a shared folder, never network code or `subprocess`); nothing is written into the folder except by *Save*; the model got no field, so files and outputs of a project that does not use the library stay byte-identical (`python -m tools.output_hashes --check docs/ui/OUTPUT_HASHES_BASELINE.json`); the blank example holds no subsystem (`tests/test_subsystem_library.py`). User page: `docs/user-manual/use-the-library.md`; pictures `docs/img/library-window.png`, `library-save-window.png` (`tools/tab_screenshots.py`, `_library_pictures`). Tests: `tests/test_subsystem_library.py`, `test_subsystem_cli.py`, `test_ui_library_window.py`.
