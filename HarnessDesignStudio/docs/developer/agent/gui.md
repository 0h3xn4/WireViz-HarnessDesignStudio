# The editor (GUI): notes for agents

These sections were moved word for word from [`CLAUDE.md`](../../../CLAUDE.md) on 2026-10-29 (decision D-182); only this introduction is new. Read them when you work in `src/harness_design_studio/gui/` (the window, the panels, the roles, the Next step page, the Systems engineer path).

## GUI layout (M2, rebuilt in October 2026)
Window (`gui/main_window.py`): the navigation rail (Next step, Home, Model, Checks, Drawings, Outputs, Revisions, Settings; `gui/areas.py` maps every main tab to an area, `MainWindow.set_area` and `go_to` open them, the six main tabs stay in `main_tabs` and each area shows its own with `SlotTabs.set_filter`), the one-row top bar and banners, the open area (Home and Settings are pages; the other areas are the tabs Diagram / Harness / Lists / Checks / Releases / Devices, Ctrl+1 to 6), the project tree and the Interfaces tab (the editable interface table, Ctrl+Shift+T) on the left, the inspector (Inspector, Why, Problems with the to-do lines) on the right, the Problems panel (a bottom dock, closed until asked for, Ctrl+Shift+M) and the status bar with the job indicator. The Next step area (`gui/next_page.py`, a page like Home) shows the one next step chosen by the pure `gui/next_step.py`; the setting `ui/role` (`systems` or `electrical`; View > Role and Settings; D-176 replaced the Simple/Full workspaces of D-171) decides whether a project opens on it and what is on screen (a settings file with no stored value asks once, *Who are you working as?*, unless the hook `roles.FIRST_RUN_ROLE` is set; one with values and no role is an Electrical / AIT engineer, a stored `ui/workspace` of 1.7.0 carries over). For the Systems engineer (the old Simple, stage S2) `_apply_role` closes the docks, turns the minimap, legend, status counts and problem notices off, reduces the tool row to Select/Connect/Add device/More and leaves Home, Drawings and Outputs out of the rail (`areas.SYSTEMS_HIDDEN`; the rail lists the area that is open); the layout is stored per role (`role_key`: `ui/simple/...`, `layout/<hash>/simple/...` for the Systems engineer, the old plain keys for the Electrical / AIT engineer); the Show panels action opens and closes the tree and inspector together. **Quick mode** (`ui/quick`, off by default; `MainWindow.quick_on`, `_apply_quick`, called at the end of `_apply_role` and on a toggle) is a view on top of any role, stored apart from the role's layout memory: `areas.hidden_in(role, quick=True)` lists only Home, Model and Settings on the rail, `TopBar.set_quick` shows **Export diagram** in place of Generate, Check, Release, Export, the hash, the revision and the chip (the fold in `_fit` / `_set_level` keeps working), `problem_notices_on()` is forced False, the status bar's job indicator does not show the automatic check (`_update_jobs`: only while `_check_asked` in Quick mode) and the tree hides its pending chips (`ProjectTree.set_quick`), there is no tour or first-start question, a project opens on the diagram (`_open_for_role`), Connect (`link_flow` -> `quick_link_flow`, `core.links.plan_quick_link`) makes the link with no window as one undo step and Add device (`QuickDeviceDialog`, `ctl.add_device_quick`) asks for a name only. It changes only what the window shows and asks, never a project file, the model hash or a written output (`tools.output_hashes --check` and `tools.numbers_snapshot --check` stay identical). **Export diagram** (`File > Export diagram…`, `gui/diagram_export.py`) writes the block diagram as SVG, PDF and PNG with no folder, harness or check; the PNG is painted with QPainter because the package has no QtSvg. There is no old bottom dock and no palette (retired in October 2026; the mapping of every old function to its new place is in `docs/ux-audit.md`, Build status, and for the shell in `docs/ui/UI_OVERHAUL_PLAN.md` section 4). The look and every decision are in `docs/DESIGN.md`; what was built for each audit issue is in `docs/ux-audit.md` ("Build status"). All files are in `gui/`:
- `devices_view.py`, `devices_dialogs.py`, `devices_pin_table.py` (the Devices tab and its dialogs and pin table), `controller.py` (EditorController: the only thing that changes the project; Delta signals; the state index and rule results the views read), `canvas.py` (scene, items, view, `CanvasMetrics`), `legend.py`, `glyphs.py`, `panels.py` (properties and problems with its to-do lines, and the small helpers other panels import), `interface_table.py` (the Interfaces tab), `command_palette.py` (the Ctrl+K overlay: a child of the window, never a dialog), `dialogs.py`, `preview.py`, `tour.py`, `theme/` (the theme package: `tokens.py` is the one source of colours, type sizes, gaps and durations; `palette.py`, `qss.py`, `style.py`, `fonts.py`, `manager.py`), `strings.py` (all UI text; append new strings at the end in a marked block).
- `areas.py` (the areas, no Qt), `rail.py` (`NavRail`), `pages.py` (`HomePage`), `settings_page.py` (`SettingsPage`: Appearance, Editing, Project, Keyboard shortcuts, About, Licences; every setting is a view of a menu action), `licences.py` (the components and their licence texts), `jobs.py` (`JobStatus`: the status bar's running job with Cancel), `problems_panel.py` (`ProblemsList`, the bottom dock; not the same as `panels.ProblemsPanel`, the inspector's to-do cards), `timing.py`, `sheet.py` (spreadsheet behaviour of a table: paste from Excel, bulk edit, Enter to edit, column menu; a model offers `is_editable` and `set_cells`), `unit_table.py` (`UnitTable`), `workflow.py` (the Generate, Check, Release steps from the facts of `ShellStatus`; no Qt), `recent.py` (recent projects in `QSettings`), `empty_state.py` (`attach_empty_state`: what a table without rows says). `shell.py`: the building blocks of the window: `SlotTabs` and `EmptyStateWidget` (a view that is not installed keeps an empty state and a hidden tab; `MainWindow.install_view(name, widget)` plugs one in), `BannerStack`, the status chip rule, `auto_scale`. `topbar.py`: `TopBar` (a full-width tool bar row: name, save marker, revision, hash, breadcrumbs, then the edit buttons, mode switch and search the window adds, the Generate, Check and Release steps, Export, status chip); it only shows what `MainWindow.shell_status()` gives it.
- `canvas_state.py`: the index id -> problems, pending values, not checked, auto, locks (`ObjectState`, `StateIndex`; no Qt, built once per change, never while painting). `canvas_badges.py`: the drawn badges, lock badge, tag chips, flight/ground zone mapping and the corner chip.
- `project_tree.py`: the `QTreeView` over a model that follows the Delta (units, interfaces, harnesses, parts, interface types, configuration, imports; counts, locks, filter). `inspector.py`: the right dock (wraps `PropertiesPanel`, lock banner, disabled fields, "Used in", values of a config file). `why_panel.py`: the recorded reasons of an object.
- `harness_view.py`: the Harness tab (header with chips, pin and wire tables, zoomable drawing from `preview.py`'s `SheetView`, the right-hand tabs Why, Edit wire, Connectors and Accessories: `wire_editor.py` with `WireEditor`, `NewWireForm`, `LabelsForm`, planned by `core/wires.py`; `connector_editor.py`; `accessory_editor.py` with `AccessoryEditor`, planned by `core/build_data.py`; each editor is in a scroll area and the four tabs sit in the third column beside the pin and wire tables, so with the tree and the inspector open the *Edit wire* form, about 320 px wide, scrolls sideways in a tab of 230 to 275 px; see `docs/UX.md` section 15). `lists_panel.py`: the Lists tab (read-only tables from `core.outputs.tables`, CSV/XLSX export of the rows shown, and `outputs_files.py`, `OutputsFiles`: the exported files with state and SHA-256 worked out in a helper thread). `checks_panel.py`: the Checks tab (rules table from `ctl.drc_rule_results()`, summary strip, `PendingValuesLink`). `config_dialog.py`: the engineering values form behind **Supply value…** (`configcheck.plan_set_value`, one undo step). `releases_panel.py`: the Releases tab (timeline, differences, change-control buttons that only emit signals). `plan_table.py`: the table of a generate preview (built, not yet in `GeneratePreviewDialog`).
- `export_dialog.py` (+ `export_docs.py`): the export window, harness x document tree; the check box *Include the open data (JSON and CSV of every result)* (`ExportDialog.open_data`; off by default, remembered as `export/open_data`; `OutputsWorker.open_data` makes `core.open_data.data_files` off the UI thread and the dialog writes them with `write_files` into `<outputs>/data/` after the outputs, outside the manifest; `verify.read_folder` skips `data/`) and the check box *Include the PDF drawings* (checked only when the folder's last export had them) decides whether the harness drawings are written, everything else always is (D-169). `import_wizard.py` (+ `import_kinds.py`): the four-page import wizard using the command line's planners. `new_project_dialog.py`: folder, name, example in one dialog. `lock_tree.py`: what a release locks or a revision unlocks, for the release and revise dialogs. `notice.py`: inline messages in dialogs.
- `tables.py` (`TableView`, `DictTableModel`, `Column`, `TableProxy`, TSV copy, saved widths), `states.py` (`StateChip`, `StateDelegate`, the twelve states), `icons.py` (Lucide paths drawn with QPainter; `icon`, `icon_button`), `background.py` (`JobRunner`: one cached job per key off the UI thread).
- Rules: tables are `tables.TableView` (never `QTableWidget`), states are `states.StateChip` or `StateDelegate` (never colour alone; pending and not checked have a pattern), icons come from `icons.py` (the package has no QtSvg), no `setStyleSheet` outside `theme/`, no `#RRGGBB` literal, font family or font size outside `theme/` (use `theme.color()`, `theme.font()`, `theme.type()` and `theme.space()`; `tests/test_theme_scan.py` fails otherwise), every string in `strings.py`, every control an accessible name and a tooltip with its shortcut, validation inline (never a message box). A new view gets its data from the controller and from headless code in `core`, never by reading files itself. A layout value of the window (panels, minimap, legend, the open area) is stored under `self._wkey(key)` (`role_key` of `gui/roles.py`), so one role's layout never overwrites the other's (`tests/test_ui_role_layout.py`); what a new control does for the Systems engineer role is decided in `_apply_role`.
- Headless logic the views read, in `core` (tested without Qt): `core/drc/by_rule.py` (one result per rule: pass, fail, not checked, pending), `core/vcs/lockview.py` (what a release locks, why, which fields stay editable), `core/vcs/timeline.py` (change log rows, differences by kind), `core/configcheck.py` (`engineering_values`, `plan_set_value`, `plan_placeholder`), `core/usedby.py`, `core/why.py`, `core/describe.py` (captions, link tooltip, unit picture), `core/generation_status.py`. Edit logic is in `core/edit.py`, `core/devices.py` (custom devices down to each pin: connectors, pins, pasted rows, inline pin checks, `device_state`, the pin-set lock of the planners; see `docs/ux-custom-devices-audit.md`), `core/checks.py`, `core/imports.py`, `core/recovery.py`; add new editor features there first, with tests, and keep the GUI thin.
- Never name a widget attribute `palette` (it hides `QWidget.palette()`).
- Panels that are not visible refresh lazily (on show). Tests that read a tab's widgets must switch to that tab first (`tests/gui_helpers.py`: `show_problems`, `win.show_interfaces()`, `win.go_to(name)`; `add_unit` and `pick_connect_type` do what the retired Palette buttons did).
- Dialog hooks (`run_dialog`, `ask_folder`, `ask_text`, `ask_choice`, `ask_file`) exist so tests can drive the UI without blocking.
- Diagram drawing rules that need no Qt live in `core/routing.py` (edge a link leaves from, orthogonal trunk routing of all links, focus of a selection) and `core/describe.py` (link values, connector family from the part); the pictures are drawn in `gui/glyphs.py` and keyed in `gui/legend.py` — show meaning with pictures, not letters or raw text; `tests/test_gui_readability.py` checks them on the flatsat example. Unit room (`edit.unit_footprints`) is the taller of the guided and expert heights, so units never overlap in either mode; `tools/build_examples.py` arranges the examples with it. Pictures for `docs/FLATSAT_EXAMPLE.md`: `python -m tools.flatsat_screenshots`. **Device looks (REQ-GUI-20):** what a device looks like comes from its kind: `core/device_kinds.py` (no Qt, so the written diagram reads it too) is the one table, `KINDS` in priority order, that reads the kind from the name, then the ID letters, the subsystem and, last, `describe.unit_glyph` (the links), unless a person set the optional, sparse field `Unit.kind` by hand (REQ-GUI-21; it is written only when set, so a project without it keeps its bytes and its model hash; `device` forces the plain box; the Kind list of the inspector is `PropertiesPanel._kind_combo`, the edit is `edit.ops_update_unit(kind=...)`); `gui/device_kinds.py` re-exports it and holds the words (`sentence`); the pictograms and badge outlines are path data in `core/pictograms.py` (16 x 16 box), which `gui/device_looks.py` turns into `QPainterPath`s and `core/outputs/looks.py` into `Shape` items for the written block diagram (REQ-GUI-22; the colours are `device_kinds.ACCENTS`, the one table the `device.*` tokens are made from); `gui/device_looks.py` draws the badge (a shape by family, the accent of the token `device.<family>` filled, the ink `accent.text`), the band on the left edge, the tint of a box seen from far away, the inspector's line and the legend's badges. The canvas has three hooks and nothing else (`UnitItem.facts().looks`, `device_looks.paint_header` and `paint_overview`, the line `device_kinds.sentence` in the tooltip); the header is not tinted because the small muted text on it is 4.5:1 only on the plain header. A new kind: one `Kind` in `KINDS`, one function in `PICTOGRAMS`, a row in the table of `docs/user-manual/telling-devices-apart.md`, a test row in `tests/test_ui_device_looks.py`. A new family needs two tokens (light and dark) that pass `tests/test_tokens.py`.
- Keep edits under 100 ms at stress size: use the Delta, never rebuild the whole scene for a local change, and never call `update()`/`prepareGeometryChange()` on the lane (zone) items or the overview map for a local edit (they are as tall as the diagram; one such call repaints every item). `tests/test_gui_perf.py` guards this by counting dirty regions.

## Roles and the Next step page (1.7.0 D-171, roles D-176)
`gui/next_step.py` (no Qt: `next_step(NextInputs)` gives the one next step and the six step lines) and `gui/next_page.py` (`NextStepPage`: shows it and calls back; the window maps each key to an existing flow; the buttons *Library…* and *Show everything* show for the Systems engineer only). `gui/roles.py` (no Qt: `ROLES`, `SYSTEMS`, `ELECTRICAL`, `default_role`, `clean_role`, `role_key`, the hook `FIRST_RUN_ROLE`) and `gui/role_dialog.py` (`RoleDialog`: *Who are you working as?*). `MainWindow._restore_role`, `_apply_role`, `set_role`, `ask_role_flow`, `_first_start_flow`, `_open_for_role`, `show_panels`, `show_everything` and `areas.SYSTEMS_HIDDEN` do the rest (see "GUI layout"). **Rules:** a role is a view, never a permission and never written into a project or the command line; nothing a role leaves out may become unreachable (menu, key, palette; `tests/test_ui_roles.py` checks it); the role is `act-role-systems` / `act-role-electrical` first, with the Settings row a view of them; the question of the first start is skipped when `roles.FIRST_RUN_ROLE` is set (`tests/conftest.py` sets `electrical`, so no test waits on it) and when the window was built with `first_run=False`; internal layout keys keep the word `simple` (`ui/simple/...`) so no saved layout is lost, and the code says role everywhere else. A stage S3 (plain words) was discarded by the owner and is not built; S4 (a blank project that asks one thing at a time) is not built. New texts go in `gui/strings.py`; tests: `tests/test_next_step.py`, `test_roles.py` (no Qt), `test_ui_next_page.py`, `test_ui_role_layout.py`, `test_ui_roles.py`. User page `docs/user-manual/choose-your-role.md`; pictures `docs/img/role-question.png`, `role-menu.png`, `systems-engineer.png`, `electrical-engineer.png` (`tools/tab_screenshots.py`, `_role_pictures`).

**S9 (D-191, D-193): three roles, the workflow and the as-built page.** `ROLES` is `(SYSTEMS, ELECTRICAL, AIT)`; `clean_role` reads a stored `electrical_ait` as Electrical (`LEGACY_ROLES`), `role_key` gives AIT keys of its own (`ui/ait/state`), `STARTS_ON_NEXT` names the roles whose project opens on the Next step page (Systems and AIT). `gui/areas.py` holds what each role lists: `HIDDEN_AREAS` (the rail) and `HIDDEN_ACTIONS` (the menus: `SYSTEMS_HIDDEN_ACTIONS` 42 entries, `AIT_HIDDEN_ACTIONS` 30, `ASBUILT_ACTIONS` for the other two), `listed_areas(role)` and `unlisted_everywhere()`; `tests/test_ui_role_pages.py` reads the window in each role and fails when a page or an entry is hidden in every role. A new action that a role should not list goes into one of those tuples, not into a condition in `main_window.py`. `gui/asbuilt_page.py` is the As-built page (it shows a `core.asbuilt.AsBuiltReport` and calls back; the window reads the sheet with `asbuilt.read_import` and runs the ops as one undo step). `NextStepPage` has the disclosure *What this step uses and makes* (`set_workflow_provider`, `refresh_workflow`: closed by default, nothing is worked out while it is closed; the report is `core.workflow.workflow_report`, which the window gives the rule check it already has) and the quiet line about engineering values still to set (`show_pending_values`, the fix of the pending-values link that the Systems engineer role switches off). The six steps of the page and the three of the top bar take their words from `core/workflow.py` (`PAGE_LABELS`, `BAR_LABELS`, via `gui/strings.py`).

## The Systems engineer path (release 1.9, W1)
`core/first_connector.py` (no Qt: `connector_choices` lists the connector parts as family, pins and gender; `plan_device_with_connector`), `core/pairing.py` (`pair_by_number`, `parse_pairing`: they only propose, returning a `links.Proposal`; the window shows it and the person presses *Accept the pairs*), `core/part_approval.py` (`approval_blocker`, `ops_approve_part`: only a person's button on the Next step card calls it). GUI: `gui/connector_picker.py`; `link_dialog.py` has `AddConnectorDialog`, `PastePairingDialog`, the proposal box and `extra_ops` (connectors made with the connection, one undo step via `ctl.add_link(first=...)`). `next_step.py` has `NextProblem` and `todo_sentence`; only a failed rule that is an error holds the page (`failed`), warnings are `warned`. `areas.SYSTEMS_HIDDEN_ACTIONS` lists the menu entries the Systems engineer role takes out of the menus (`MainWindow._hide_menu_entries` removes them from the menus; never `setVisible(False)` on an action, Qt then switches its shortcut and `isEnabled()` off and the palette loses it). `release_text.plain_blocker` words core blockers for the screen. New texts are in the block "1.9 W1" at the end of `gui/strings.py`.

## Polish layout (M7)
User guide `docs/guide/USER_GUIDE.md` (HTML bundled in `src/harness_design_studio/resources/guide/`, F1), `docs/RULES.md` (generated), `docs/CONFIG.md`, `docs/usability/`, Ubuntu packaging in `packaging/ubuntu/` and `tools/build_deb.py`, `tools/release_check.py`, `tools/soak.py`.
