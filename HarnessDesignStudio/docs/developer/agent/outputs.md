# Outputs and the build workbook: notes for agents

These sections were moved word for word from [`CLAUDE.md`](../../../CLAUDE.md) on 2026-10-29 (decision D-182); only this introduction is new. Read them when you work on a written file (`core/outputs/`, the independent verifier, the goldens) or on the build data.

## Outputs layout (M5)
`core/outputs/` (`canvas` SVG/PDF writers, `drawing`, `system` diagrams, `tables`, `buildsheet` the build workbook of a harness (D-169: styled write-only openpyxl workbook, no formulas, deterministic; the verifier reads it cell by cell), `exports` YAML/JSON/XLSX, `stamp`, `build` build/write/status, `verify` independent verifier). Format and limits: `docs/OUTPUTS.md`. `build_outputs(project, drawings=True)` has the drawings on by default as a library call; `harness-design-studio export` and the Export window pass `drawings=False` unless `--drawings` or *Include the PDF drawings* is chosen, and `drawings_exported(folder)` tells whether the last export had them (the self-check accepts a set with the drawings of every harness or of none).
- `build_outputs` is pure and deterministic: no dates, sorted rows, uncompressed PDF, XLSX re-zipped with fixed timestamps. Keep it that way; goldens depend on it.
- `core` must not import modules that import network code at import time (`xml.sax.saxutils` does; use `canvas.escape`). The offline test catches this.
- `core/outputs/verify.py` must stay independent of `tables.py`/`drawing.py`: derive expectations from the project.
- Connection list (release 1.9, W2, REQ-OUT-09): `core/outputs/connections.py` builds `system/connections.csv` and `system/connections.xlsx` (styled like the build workbook, deterministic), written by `build_outputs` **only when `project.links` is not empty**, so a project without links keeps byte-identical files. Links are also edges (tagged with the link ID) in `system.block_diagram` and rows (with a `Kind` column, header `Interface or connection`) in `tables.traceability`, again only with links. `verify.py` re-derives every cell of these on its own (`_connections`, `_trace_rows`; the interface cell is checked to be possible, not rebuilt). `export` (CLI and the Export window) needs a harness **or** a link. `tables.py` cannot import `core.links` at module level (import cycle through `core.devices`).
- Signal, interface and requirement (release 1.10, D-184, REQ-OUT-07): in the pinout tables a cable pin without a signal of its own shows the signal and the interface of the wires that end on it (`tables.wire_signals`, different values sorted and joined with `;`; `_pin_rows(..., carried)`; the verifier derives them again with `_harness_carried`); a pin of its own keeps its value. The wire list gets a *Requirement* column after *EMC class* and `traceability.csv` one after *Routed* (before *Kind*) only while an interface has a `requirement_id` (`tables.uses_requirements`; `verify._trace_header`), so a project without requirement IDs keeps both tables. `tests/test_signal_requirement_columns.py`.
- Units of `export.json` (release 1.13, D-195): the object `field_units` comes from the one table in `outputs/export_units.py`; a numeric field added to the model needs an entry there (`tests/test_export_units.py` fails without it); `verify.py` reports `out_json` for a number with no unit when the file has `field_units`.
- Pair parts (release 1.11, D-188): the BOM (`tables.bom`) and the mass (`generate/mass.py`, and `tables.mass_length` through it) divide a wire's length by `Part.conductors`; `verify.py` does the same on its own in `_bom_rows` and `_mass`, so a change to one counting rule must change both. Only the BOM, the mass table and `export.json` of the examples changed with it. `tests/test_pair_part_counts.py`.
- Adding an output file: build it in `build_outputs`, add its check to `verify.py` with a mutation test, regenerate goldens, document it in `docs/OUTPUTS.md`.

## Build data layout (1.7.0)
`core/build_data.py` (D-170: `plan_set_strip`, `plan_set_strip_all`, `plan_set_contacts`, `plan_set_part_tool`, `plan_set_accessory`, `plan_delete_accessory`, `check_accessory`; pure plans of ops, one undo step, a released harness refuses with the reason) and `core/build_data_import.py` (`plan_build_data_import`: the kind of table is told by its headings, every row gets a verdict, a refused row stops the whole import; used by `cli/data.py` `import-build-data`). The data: `Wire.strip_a_mm`, `Wire.strip_b_mm`, `Pin.contact_part`, `Part.tool`, `Harness.accessories` (a list of `Accessory`); all sparse (`OMIT_WHEN_DEFAULT`, left out of the files while empty) and a person's values: the tool computes nothing from them and sets no default. Generation keeps them (`generate/engine.py`; the contact of a unit pin is copied to the cable pin, so for a generated harness it is set on the unit's pin in the Devices tab). `core/integrity.py` has `dangling_accessory`; `vcs/diff.py`, `vcs/snapshot.py` and `vcs/lockview.py` carry accessories and the contact parts for change control. Where the values show: optional columns in `outputs/tables.py` (only when used), `accessories.csv`, and always in the build workbook (`core/outputs/buildsheet.py`, whose cells read *to fill in* when empty); `outputs/verify.py` checks all of it. Editing: *Edit wire* (strip lengths), the Devices pin table (*Cable contact…*), the Connectors and Accessories tabs, the Inspector (*Crimp tool* of a contact part). Templates: `strip-lengths.csv`, `pin-contacts.csv`, `accessories.csv`. User manual: `docs/user-manual/enter-the-build-data.md`.
- Block diagram looks (REQ-GUI-25): `core/outputs/system.py` draws each card of `system/block_diagram.svg|pdf` (and Export diagram, `gui/diagram_export.py`) with a band and a badge from `core/outputs/looks.py` (a `Shape` item of `core/outputs/canvas.py`: SVG `<path>`, PDF `m l c h` operators, painted by `gui/diagram_export.py` and `gui/preview.py`), in the light colours of `core/device_kinds.ACCENTS`, plus a key to the kinds. Only `block_diagram` has them (`_diagram(..., looks=True)`); `harness_overview` is as it was. Coordinates are rounded when made (`core/pictograms.py`) and written with three decimals, so the bytes are the same on every platform. Changing a look renews the block diagram entries of `docs/ui/OUTPUT_HASHES_BASELINE.json`, `tests/fixtures/numbers/snapshot.json` and `tests/fixtures/outputs` with the tools, with a reason in `docs/changes.md`.
