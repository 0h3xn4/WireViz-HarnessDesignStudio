# The trace of 16 numbers, repeated

Generated by `python -m tools.trace_numbers --update`; do not edit by hand. Decision D-191, stage S10 of [the plan](transparency_plan.md).

The [audit](transparency_audit.md#8-the-trace-test-16-real-numbers) traced 16 real numbers back to their inputs by reading code, files and documents, and no number took under 3 minutes. This page is the same test made with only what the tool offers: `explain` (or `api.explain`), `export-data` and `settings --json`. For each number the test checks that the answer is complete (an equation; every input with a source; every configuration key it names is a setting that `settings --json` lists; every assumption it rests on is listed there; what is not set is named), that the number equals the same number in the files of `export-data` where those have it, and that all of it took less than a minute (`tests/test_trace_16_numbers.py`). The seconds are not in this file, so that it stays the same bytes for the same tool; `python -m tools.trace_numbers` prints them.

The numbers are those of the packaged examples with their example engineering values (`flatsat`, `first-steps`), which are not engineering data. Where the value of the audit has moved with the example, the row names the equivalent number.

## What this does not show

- It shows that each number can be traced with the tool in under a minute, not that the number is right for a programme: the example values are placeholders and the tool records no standard for them unless the project names one.
- The time is that of a machine running the tool in one process; a person reading the derivation takes longer than the tool takes to give it. The audit's minutes were a person's; these are the tool's seconds, and the claim is that no step needs the code, a file search or a document any more.
- The *decision* of a gauge (why 24 and not 26) is made by Generate: the derivations show the limits of the gauge that is on the wire, not the search that chose it, which is described on the [wire sizing](models/wire-sizing.md) page.
- Nobody has looked at the screen for this test: the Why tab shows the same derivations (`render`), and its pixels are not part of it.
