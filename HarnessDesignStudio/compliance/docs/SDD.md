## 4. Software design overview
- **4.1 Static architecture:** layers `core` (no GUI, CLI or network imports), `cli`, `gui`, `resources`. Components of `core`: `model` (strict immutable pydantic models of the logical and physical layer), `io` (folder format, atomic saves, migration, recovery), `commands.py` (transactions, undo and redo), `generate/` (segmentation, pin allocation, sizing, lengths, mass, naming, explanation), `drc/` (design rules, standard rules, report, helper process worker), `outputs/` (tables, drawings, system diagrams, exports, stamp, independent verifier), `vcs/` (release, locks, diff, baselines, change log), `verify.py` (independent verifier of the wiring), `edit.py`, `checks.py`, `imports.py`, `kicad.py`, `library_import.py`, `configcheck.py`, `standard_profiles.py`, `templates.py`, `starter.py`, `samples.py`, `devices.py` and `pinout_import.py` (custom devices down to each pin and the pinout import), `describe.py`, `why.py` and `usedby.py` (captions, recorded reasons and where-used for the views), `integrity.py`, `issues.py`, `errors.py` and `ids.py` (referential integrity, findings, error types, identifier rules), `generation_status.py`, `recovery.py` (autosave journal), `routing.py`, `schemas.py`, `units.py` and `wirecolours.py`.
  The `gui` layer (the Qt editor, PySide6) changes the project only through `controller.py`. Since 1.3.0 (D-150 to D-159) its parts are: the theme package `gui/theme/` (tokens, palette, style sheet, widget style, bundled Inter and JetBrains Mono fonts, theme manager; it replaced IBM Carbon and `gui/tokens.py`), the shell (`main_window.py`, `shell.py`, `rail.py` and `areas.py` for the navigation rail and its areas, `topbar.py` and `workflow.py` for the top bar with the steps Generate, Check and Release), the pages `pages.py` (Home) and `settings_page.py` (Settings), the Problems panel `problems_panel.py`, and the views and dialogs listed in `../../docs/ARCHITECTURE.md`. Since 1.4.0 (D-160 to D-165): in `core`, `wires.py` (the plans behind editing, drawing and grouping wires and setting labels), `device_library.py` (device library files) and `vcs/gitinfo.py` (the last commit, read from the `.git` files without starting `git`); in `gui`, `wire_editor.py` (the Edit wire tab) and, in `devices_dialogs.py`, the dialog that adds devices from a library file. Since 1.5.0 (D-166, D-167): in `core`, `manual_harness.py` (a harness that a person builds from nothing: its cable connectors and their pins); in `gui`, `connector_editor.py` (the Connectors tab of the Harness tab) and `startup_help.py` (why the editor did not start on Linux and the `--check-system` check; it does not import Qt and starts no program). 1.6.0 (D-168) removed the macOS build code and added no module. The list of every `gui` module with its purpose is the generated `../sdd_components.csv`.
- **4.2 Dynamic architecture:** a single process with a Qt event loop; generation runs in a worker; the design rule check runs in a helper process (D-128); the GUI only changes the project through `EditorController` and `History.execute`.
- **4.3 Behaviour:** generation is a pure function of the design (`plan_generation`) that returns operations, a report and a provenance record; the user previews and applies the plan as one undoable step.
- **4.4 Interfaces context:** `ICD.md`.
- **4.5 Long lifetime software:** the project format carries a schema version and migrations keep the original files.
- **4.6 Memory and processing budget:** stress project of 200 units, 2 000 interfaces, 20 000 wires: generation under 10 s (REQ-PERF-02), editor edits under 100 ms (REQ-PERF-01); measured with `tools/bench_gui.py`, `tools/bench_generate.py`.
- **4.7 Design standards:** `STANDARDS.md`.

## 5. Software design
- **5.1 General, 5.2 Overall architecture:** as 4.1. Mandatory design rules (determinism, verifier independence, no network) are tested where stated in `STANDARDS.md`.
- **5.3 and 5.4 Components:** every module of the package is a component; `../sdd_components.csv` lists, for each, the identifier (module path inside the package), the layer, the purpose (first line of the module docstring, a test fails if one is missing) and the components it imports. The table is generated by `python -m tools.gen_sdd_components` and a test fails when it is stale. On 2026-10-21 it had 159 rows: 85 in `core`, 67 in `gui`, 5 in `cli`, the package itself and `resources`.
- **5.5 Internal interface design:** transactions (`Op`: `Put`, `Delete`, `SetConfig`, `DeleteConfig`), the `Delta` signals of the controller, the chunked messages of the helper process.

## 6. Requirements to design components traceability
Requirement to verifying file: `../traceability.csv`. Requirement to component: `../sdd_components.csv`, columns `requirements` (the requirement names the module in its "Verified by" column, or a test file it names imports the module) and `requirements_indirect` (the module is imported by a component reached directly, so the code runs under that requirement's tests). Modules with both columns empty are visible in the table; they are covered only by tests that do not carry a requirement ID. On 2026-10-21, 79 modules were reached by a requirement directly and 153 directly or indirectly. A direct requirement-to-component statement still needs a person (review) where the table is empty.
