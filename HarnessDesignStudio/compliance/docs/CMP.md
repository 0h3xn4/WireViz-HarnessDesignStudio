# Configuration management plan

Status: approved by the owner on 2026-10-08 (approval given in the working session; the owner is also customer and supplier, so no independent reviewer, see A-01).

Addresses ECSS-Q-ST-80C 6.2.4.1 to 6.2.4.12 and ECSS-E-ST-40C 5.3.2 (gaps G-14, G-07). ECSS-M-ST-40, referred to by 6.2.4.1, was not supplied; this plan does not claim to meet it.

## Items under control

All files of the repository folder `harness/` (source, tests, tools, documents, compliance records, packaging), the pinned dependency versions in `pyproject.toml`, and the delivered packages.

## Baselines

| Baseline | When | How identified |
| --- | --- | --- |
| Development | every commit on a working branch | commit id |
| Review | state sent to a review | tag `review-<name>` on the commit (to be created by the owner when a review is held) |
| Release | when `docs/RELEASE.md` is passed and the owner signs off | tag `v<version>` and the file `scf.json` of `python -m tools.gen_scf` |

## Change control

Changes are made on a branch, one commit per logical change, the message names the requirement or gap it serves (for example `G-07; ECSS-Q-ST-80C 6.2.4.11`). A pull request is opened for the owner to review and merge; the CI checks must pass. A problem report (SPR) is the reason for a correction. Branching and merging (6.2.4.12): topic branches from the default branch, merged by pull request; a release is never made from an unmerged branch.

## Status accounting

`git log`, `CHANGELOG.md` (what changed, what is open) and the SPR list. `compliance/traceability.csv` and `compliance/compliance_matrix.csv` are regenerated by the tools named in them and checked by tests.

## Integrity of deliveries (6.2.4.8 to 6.2.4.11)

`python -m tools.gen_scf` writes `scf.json` and `SHA256SUMS` (SHA-256 of every delivered package, aggregate SHA-256 of all source files). The recipient verifies with `sha256sum -c SHA256SUMS`. The checksum protects against accidental change, not against an attacker who can replace both files; signing the release is open action A-08.

## Delivery information (6.2.4.11)

For each delivery: version, source commit, list of dependencies with versions (`scf.json`), SBOM and licence report (`python -m tools.gen_sbom`), changelog entry, known open problems (`CHANGELOG.md`).

## Documents under control (6.2.4.7)

All documents are in the repository and so under the same control; the documents controlled are the plans, specifications, design, test and release documents listed in `compliance/docs/` and `docs/`.
