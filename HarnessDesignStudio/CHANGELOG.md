# Changelog

Versions follow semantic versioning. Every project file records the tool version that saved it.

## Unreleased

### Added

Look and feel
- Theme: View > Theme offers System (the default, follows the operating system's light or dark scheme), Light and Dark; the choice is stored in the settings.
- Vector icons (from Lucide, ISC licence, drawn in code) for the toolbar and panels: zoom in, zoom out, fit, search, import, undo, redo and the panel close buttons have an icon and a tooltip that names the shortcut.
- State chips for pending, not checked, locked, released, out of date, pass and fail: icon, word and, for pending (dotted) and not checked (hatched), a pattern, so colour is never the only sign.
- Shared table code (`gui/tables.py`): right-aligned numbers, units in the header, sorting, filtering, Ctrl+C copies the selected cells as tab-separated text, column widths are remembered.

Diagram
- Several items can be selected (Shift-click, Ctrl-click, a rubber band, Ctrl+A); Properties shows what they have in common, and they are moved, deleted, aligned, spaced out and duplicated as one undo step (Ctrl+D, Edit menu, right-click menu).
- Find with Ctrl+F marks units and links; a right-click menu offers the same actions as the menus, with the reason for each greyed entry, and "Add unit here"; a grid and View > Snap to grid (Alt places freely).
- Marks on every unit card and link label: problems, warnings, values still to enter and "not checked yet" as a badge (icon and count); units, links and connectors that a release locks show a lock and "W001 A" and a faint released tint; the legend lists only the marks that are on the diagram. A click on a badge selects the object and asks the window to show its problems (the window does not act on that yet).
- A corner chip says whether the harnesses and the outputs are out of date, not generated, not exported or up to date.
- The "n auto" chip and the tooltip of the Auto badge say why the tool chose a connector and that it is not confirmed yet. "Why?" in the right-click menu asks the window for the same (not connected to a panel yet).
- Cards show a picture of their kind of unit, the number of connectors ("12 conn"), "+3" where connector pictures do not fit, and the "n auto" count in Guided mode too; FLIGHT or GROUND can be set per zone from the unit's menu (a viewer setting, not in the project file).

New views
- Harness tab (`gui/harness_view.py`): a header with the harness, its release state, its interfaces, the hash Generate last read and chips for design, outputs and independent check; a connector and pin table (locked pins carry a lock and name the release that locks them; pending values and auto-filled rows have their own chips), a wire table, a zoomable drawing and a Why pane for the selected wire, connector or pin, all linked by hover and selection.
- Lists tab (`gui/lists_panel.py`): the wire list, pinouts, BOM, mass and length, test tables, labels and the system BOM as sortable, filterable tables with units in the headers, Ctrl+C as tab-separated text, a banner when the design changed after Generate, and export of the visible rows as CSV or Excel ("Export table").
- Checks tab (`gui/checks_panel.py`): one row for each of the design rules with its result (pass, fail, not checked, pending), a summary strip ("34 rules: 20 passed · 2 failed · 12 not checked · 4 pending values"), the requirement IDs of each rule, the offending objects (Enter or double-click shows one), and the exact configuration value a pending rule waits for. A check that is running can be cancelled, and a failed check leaves a banner until the next one succeeds.
- Releases tab (`gui/releases_panel.py`): the timeline of reviews, releases and new revisions of every harness with state chips, the differences between two revisions or a revision and the working design grouped by kind with counts (values read "(none)", never `None`), and Submit for review, Release and New revision per harness.
- Project tree (`gui/project_tree.py`, left panel): Units, Interfaces, Harnesses with their release state, Parts, Interface types, Configuration with its placeholder and pending values, and the import entry points; problem counts and a lock on every object, a filter, keyboard navigation and an "Add" menu. It updates only the rows a change touches.
- Inspector (`gui/inspector.py`, right panel): tabs Inspector, Why and Problems; a banner that says why an object is locked and offers "Start new revision"; fields a release forbids changed are disabled with the reason; "Used in" lists the links, harnesses and wires that use a unit, link, part or interface type; a configuration file lists its engineering values with a status chip each.
- Why panel (`gui/why_panel.py`): the recorded reasons for a unit, link, harness, wire, connector or pin as "rule: sentence" lines, what is still pending and the placeholder files generation used.
- Devices tab (`gui/devices_view.py`, Ctrl+6): one unit down to each pin: its state (draft, in use, locked, read-only), its connectors and their cards, a pin table with signal, mode, interface, direction and class taken from the interface type (never guessed), wire and state, notes about the pins, and the pinout as exported with Export pinout (CSV or Excel). The unit selected on the diagram or in the tree is the device shown.
- Devices tab, editing: cells of the pin table are edited in place (pin name, signal from the project's interface types or free text, mode, contact size, termination) with F2 or Enter, Tab, Insert, Delete, Shift+Delete, Space and paste from a spreadsheet; each action is one named undo step ("Edit pin J01.A2", "Paste 9 pins into J01"). Add > Device… (Ctrl+Shift+N) makes an empty device; connectors are added from a part picker with New part…; "Fill from interface type…" (Ctrl+L) and "Assign to interface…" (Ctrl+Enter) put signals and interfaces on selected pins. A part or interface type made here is marked pending or unverified; the tool never approves it. A released device shows the lock banner with Start new revision; the pin set of a connector that a released cable mates with cannot be changed.
- Changing the part of a connector now also gives it the part's pin count and gender (the Inspector does it at once, the Devices tab asks first); before, the pins and the gender stayed as they were.
- A table for the generate preview (`gui/plan_table.py`): each harness with whether Generate creates, changes, removes or leaves it, and the locked pins that stay. It is not in the Generate preview window yet.

Dialogs
- Export window (`gui/export_dialog.py`): output folder, a harness by document tree, progress with Cancel, and the list of files written with Reveal in folder, Open, a picture of the selected drawing and Copy selection to folder. A failed independent check or write error is a notice in the window that stays. The export still writes the full set.
- Import wizard (`gui/import_wizard.py`): approved parts, segment lengths, the ampacity table and a KiCad netlist (interfaces too, though Ctrl+Shift+I still opens the older window) in four steps (file, columns with a live preview, conflicts and placeholders with the exact reason for each row, apply); every import is one undo step called "Import n rows". File > Import lists every kind.
- New project window (`gui/new_project_dialog.py`): folder, name and example in one dialog with the problems said next to the field.
- Engineering values form (`gui/config_dialog.py`): **Supply value…** on a pending rule (or Design > Engineering values…) opens every engineering value grouped by config file, with units, the placeholder flag, inline reasons for a refused value and locked values disabled with the reason; Apply sets all changes as one undo step and the checks run again.

Window
- Top bar (`gui/topbar.py`): project name, short model hash in mono, a dirty marker, **Generate** (the one primary button), Check, Export… and a status chip (up to date, plans out of date, outputs out of date, generating, exporting, checking). Ctrl+G generates, Ctrl+E exports, F5 runs the checks.
- Persistent banners: when the plans or the exported files no longer match the design a notice stays under the top bar with Generate and Export buttons; a failed generate, export or check stays as a notice until the next success.
- Main tabs Diagram, Harness, Lists, Checks and Releases (Ctrl+1 to Ctrl+5), the project tree and palette on the left, the inspector with its Why and Problems tabs on the right; a link double-click opens the Harness tab.
- A status-bar link "n values pending · n rules not checked" that opens the Checks tab filtered; the status bar also shows the project folder (monospace, cut in the middle when narrow), the number of rules and the tool version, "Generated at model xxxxxxxx" and the zoom level.
- F6 and Shift+F6 move the keyboard focus between the diagram, the project panel, the inspector and the bottom panel; Ctrl+I adds an interface; the Connect tool is in the Edit menu; every shortcut is in a menu and in the tooltip ("text (shortcut)").
- View > Reset layout; the dock layout is saved with the window.

### Fixed

- LVDS and RS-422 no longer share one picture: LVDS shows a differential pair closed by a termination resistor (a test fails if two kinds of link share a picture, apart from primary and secondary power, which differ by colour and name).
- A link's label in the diagram keeps clear of the other links: it is placed where no other link runs through it, and where there is no such place a smaller label (the picture alone) is used. On the flatsat example 10 of 44 labels still touch another cable (before: 28).
- A review, release or new revision cannot be dated before the last change-log entry of the same harness (`date_before_last`).
- `harness new --name` with a blank name is refused, and a name is stored without surrounding spaces. A link (also a dangling one) is not accepted as the folder of a new project, with the usual "not an empty folder" message.
- `import-lengths` help, `IMPORTS.md` and the templates README say that its three columns are read by position. The exit code table in `CLI.md` names the imports and `config` under exit code 1.
- `FILE_FORMAT.md` and `TROUBLESHOOTING.md` describe the empty `.harness.lock.takeover` file.
- **Fixed: outputs, low findings** (audit D-12, D-14, D-17). Wires with both ends on one side of a cable block (loop-back plugs) are counted when the drawing is split into sheets, so their loops no longer run into the title block. A damaged output manifest that lists a folder no longer makes every export fail; the empty folder of a removed harness is removed; the deep output check treats a linked output file as changed and the output reader skips links. The routing function names a missing gap instead of raising a key error.
- The package self-test (`--selftest`) no longer leaves a temporary folder behind, names the step that failed, works when `QT_QPA_PLATFORM` is set but empty, and only reacts to its flag as the first argument.
- The `.deb` no longer carries the tarball-only `README.txt`, icon and desktop template under `/opt`.
- The CI run on a merge to `master` is no longer cancelled by the next merge; the documents-only job also runs the flatsat walkthrough test; a missing `.deb` or `.tar.gz` fails the build job.
- The wheel carries the `.gitignore` files of the example projects; `tools.vendor` no longer downloads an unpinned `wheel`; a licence such as "GPL-3.0 with LGPL exception" is rejected by the licence report.
- `harness verify` on a project without wires says to run `harness generate` first.
- `harness config` no longer names decision-log numbers (D-10, D-15).
- Documents: locking a wire or pin is done by editing the harness file (the app has no button); `emc.classes` is documented as read by no rule.
- Build tools: a failing example builder keeps the old example folder; `tools.metrics --coverage` and `tools.usability_summary` give a message instead of a traceback; `tools.extract_requirements` checks that all PDFs exist before it rewrites any list; the user-guide converter keeps code spans and link targets intact.
- A two-colour wire written `yellow/green` or `green-yellow` shows both codes (`YE/GN`) in the drawing instead of a cut-off word; it is still drawn grey (audit B-19).
- `forbid_nominal_with_redundant: false` now lets nominal and redundant interfaces share a harness, and `category_pairs_to_separate` separates only the pairs it lists (audit B-17).
- The mass table header says it covers wires and cable connectors; backshells, shielding, sleeving and tie-downs are not in the mass (audit B-21).
- The Explain tab no longer says "(X drives)" for power and other single-path signals, names the connector on each pin line, and shows the "stays on pin ... because the pin is locked" line; a missing mating part is no longer written as "mates with itself" (audit B-16).
- Arranging the diagram twice changes nothing more, also at stress size; a fixed pin with no signal is never given to an interface; a branch name cannot equal a cable connector ID (audit B-22).
- **Fixed: editor, small items** (audit F1-26, F1-27, F2-10). A number typed with other scripts' digits (Arabic-Indic, full-width) is refused in the number fields and the table. An unknown chain typed into the interface table is refused with a plain message. The names of the steps in the Undo menu, the table headings and a few words on the diagram moved into `strings.py`. The accessible-name test no longer accepts a tooltip as a name.
- Loading a project with many set-aside objects reads and scans each file once (it was quadratic: 32000 bad units took 30 s). Audit A-13.
- The undo history keeps the last 200 steps, and an edit with no operations is no longer an undo step (it also cleared redo). Audit A-14.
- Names refuse line and paragraph separators, the byte-order mark and private-use characters; dates (library, release, change log) must be exactly `YYYY-MM-DD`; zone names in `layout.json` are checked like other names. Audit A-16.
- The integrity check reports a part that mates with itself or a missing part, a baseline of a missing harness or with an ID that is not `<harness>.<revision>`, baselines whose IDs differ only by case, and (as warnings) a connector for a missing interface type and a change log entry of a deleted harness. The integrity cache follows the generated flag of the owning harness. Audit A-15, A-17.
- The connector-manufacturer rule ignores case and spaces; emc-class-split also sees interfaces named only by wires; wire-spec and mating-cycles findings can be shown; `config --apply-profile` says when the plans became out of date. The verifier no longer imports the generator. Audit C-22, C-23.

## 1.0.0 (2026-10-12; released on the owner's instruction, see compliance/SIGNOFF.md; not a statement of compliance)

Version 1.0.0 is 0.1.0 plus the changes listed below: the fixes of the October 2026 pre-release audit (the findings and what was done about each are in `AUDIT.md` at the root of the repository), the release freeze of parts, interface types and configuration, two more examples (`minimal-satellite`, `flatsat`), a design worksheet template and the wiring-diagram drawing. The open engineering decisions were recorded as defaults on 2026-10-12 (`docs/DECISIONS.md` D-142 to D-145); the tool still ships no standard or part data. **What is still true**: the configuration files are placeholders and the parts are example parts, so results rest on placeholders; no compliance with any standard is claimed; the packages are not signed; the upstream WireViz code under `src/wireviz/` is unchanged.

- **Fixed: a release freezes the parts, interface types and configuration it uses** (audit E-5, I-2). The baseline now also records the parts, interface types, configuration values and waivers of the released harness (old baselines without them still load and are written back unchanged). While a harness is released, the editor and the data commands refuse to change or delete a part, interface type or configuration value it uses, and `harness check` reports a hand edit as *released-modified*. Adding parts, editing parts no released harness uses, notes and names stay allowed. The exact list is in `docs/FILE_FORMAT.md` ("What a release freezes").
- **Fixed: impossible numbers** (audit A-6, D-9, B-18, K-19). A wire gauge outside AWG 0 to 40, a length below 0 or above 10000 m, a current or voltage of 0 or less, a pin count outside 1 to 1000, a negative mass or rating, a harness number below 1 and a schema version below 1 are refused by the editor and set aside on load (reported, kept), instead of reaching the outputs.
- **Fixed: locks and saving** (audit A-7 to A-12). A project lock from before a restart, or whose process number was reused, is taken over; the lock error names the lock file and, for another computer, how to remove it. Saving no longer copies the content behind a link into a `.bak` or the migration backup; a migration backup that is a link is refused and the backup is built under a temporary name; new files follow the umask; a folder that is not a project gets no lock helper file; temp files left by a killed save are removed by the next save. The editor schemas: `library/manifest.json` has its own schema only, and IDs carry their pattern.

- **Fixed: outputs, medium findings** (audit D-3 to D-18, G-7, I-4). A pin ID is drawn whole (smaller, or in a wider pin column) instead of cut to `SHIELD~`. The CSV guard against formulas can be undone exactly, so a signal that starts with `'` plus `=`, `+`, `-` or `@` exports and verifies. `titleblock.fields` is checked (unknown or repeated names and non-text entries are a configuration error) and `sheet` may be left out. Characters a PDF cannot show are named in a warning. A shield keeps its end A on every sheet. The box pinouts, the mating matrix and the JSON export no longer depend on the order the harnesses were created in. The output check now compares every cell of the pinouts, BOM, tests, labels, mass table, mating matrix, traceability, box pinouts and DRC findings, the YAML values, the pins and signals in the drawing, the PDF texts, the XLSX sheets and the provenance values. A workbook that cannot be built (a full temporary folder) gives a message that says why. The harness overview draws every pair of units of a harness, a routing sketch no longer cuts a segment length, and a signal name keeps its double spaces in the labels. XLSX files are written without lxml, so they are identical on every machine. The SVG drawings changed (pin texts carry a label), so the output golden digests were regenerated.
- **Fixed: diagram editor** (audit F2-4 to F2-14). The key under the diagram follows the kinds of link in use. A unit cannot be dragged past the top or left edge, and the scene grows to hold units placed far out. The Connect tool no longer drags a unit on screen without moving it in the project. Switching to Expert grows the scene. Link labels are placed again when their numbers change. The outline clears its highlighted row when nothing is selected. Long unit IDs and connector names end in an ellipsis. A line break in an interface name typed into the table is refused. The tour skips steps whose panel is hidden and does nothing on a closed window.
- **Fixed: installer scripts** (audit G-2, G-3, G-4, G-13). `install.sh` writes a list of what it installed (`.harness-design-studio-install`); `uninstall.sh` removes only the folders on that list and refuses to touch a `cli`, `LICENSES` or `_internal` folder that it did not install (before, it deleted them and said "Your projects are not touched"). `install.sh` refuses to install into the folder that holds the unpacked package (it deleted the package), copies to a temporary name before replacing the old install, and makes the files belong to root in a root install. The tarball is built with owner root, sorted entries and fixed times. A link in the bin folder that points to another program is not replaced; `--prefix ""` is refused; `uninstall.sh --help` works; one install's uninstall keeps the launcher of another.
- **Fixed: release gate and packages** (audit G-5, G-6, G-8, G-9, G-11, G-12). The release check fails when the version is already a git tag or `## Unreleased` still has text, runs the tests with `HARNESS_REQUIRE_BROWSER=1`, prints the number of skipped tests and fails on any skip except the permission tests that need a non-root user (when it runs as root). The release image has poppler and Chromium. The `.deb` is reproducible without `SOURCE_DATE_EPOCH` and depends on `libc6 (>= 2.39)`. `gen_scf` fails when there is no `.deb` or `.tar.gz` and leaves `*.egg-info` out of the source manifest. The soak test's undo-then-redo check now compares the model.
- **Fixed: CI template and documents** (audit G-10, G-14, G-17, K-6 to K-8, K-13, K-15, K-16). The GitHub Actions template runs `harness drc` like `build.sh`; the tool's own workflow has read-only token rights. The in-app guide no longer breaks a table row with an escaped bar. The tests compare the output quoted in `GETTING_STARTED.md` and `docs/examples/README.md` with what the tool prints, and cover all Markdown under `docs/` for links; the flatsat export count is 112, the library list in the install notes has all 14 packages, and a few wrong sentences in the CLI reference, cheat sheet and guide are corrected.
- **Fixed: release record, damaged files and locks** (audit of 2026-10-10). A release or new revision that was saved can no longer be undone (undo is off for that step; before, Release, Save, Undo, Save removed the baseline and the change-log entry from disk). A project file that is a link, over 64 MB or unreadable now counts as damaged: the project is "recovered" and cannot be saved over its folder (it was moved to `.bak` and regenerated). A lone surrogate escape (`\ud800`) in a project file makes the file invalid, instead of loading clean and crashing every save. New check `wire_to_itself` (a wire that starts and ends on the same pin). `harness check` and the rule *released-modified* also compare the units and box connectors stored in the baseline; the design fields of a unit of a released harness are locked like those of its interfaces.
- **Fixed: generation on bad input** (audit B-1, B-2, B-4, I-1). A generation result that holds only errors is no longer "nothing to change" (`empty` is false and the summary lists the errors). Generation checks the configuration first: invalid values (a derating factor above 1, an ampacity table that falls with wire size or has a gauge outside 0 to 40, a negative or fractional pin gap, a number given as text, a wrong `default_gauge_awg` or `wire_colour_by_signal`) are reported as errors and treated as unset instead of crashing or being used. A naming template that raises, gives a reserved name (`COM1`), or repeats itself no longer crashes or hangs; it falls back to the default with a warning, shown after the names are made. A locked pin that already carries a signal is kept on a connector with a fixed pinout, and a locked fixed pin keeps its interface (it used to be cleared and the harness dropped).
- **Fixed: generation and editing, medium findings** (audit B-5 to B-15, B-20, B-22).
  - A harness naming template whose default fallback names would be too long is refused with a warning (it used to crash).
  - Locked power pins now count for the power-to-signal pin gap. Pins of an interface that could not be placed are given back to the next one.
  - The generation status turns stale when a manual harness takes over an interface. Releasing a harness still does not.
  - A locked wire or an entered segment length that regeneration cannot carry over is named in a warning (`locked_data_lost`). In per_unit_pair mode a renamed unit keeps its harness IDs, locked wires and lengths when the interfaces are the same.
  - A redundant copy of a unit no longer copies the pin assignments of the original (locked and fixed pins keep their signal).
  - Deleting a unit is blocked by manual harnesses that plug into it.
  - Interfaces with both ends on one connector, with fewer than two ends, or of a type with a repeated signal name are skipped with a finding instead of being wired onto one pin.
  - Zone names are checked; a project with no zones can be edited (one implicit lane).
  - Editing operations raise a plain `EditError` for unknown IDs, bad IDs, a repeated interface ID and a wrong end number. The compatibility checks no longer scan all interfaces for every connector.
- **Fixed: verifier and design rules** (audit of 2026-10-10). A wire with the same pin at both ends no longer stops `verify` and `drc` with an internal error: it is a verifier error (`wire_same_pin`; a wire between two pins of the same end is `wire_same_end`). The verifier now also compares the wire's signal label (when set) with the signals of the pins it reaches (`wire_signal_mismatch`) and the signal and interface written on a cable-side pin (when set) with the unit connector's pinout (`cable_pin_mismatch`), so two wires with exchanged pins are found. A temperature-margin error is now reported on each connector or wire that uses the part, so it blocks the release of the harness that uses it (it blocked none before). The "not checked" note now also names wires and harnesses whose current or voltage drop could not be checked (no bundle factor for that many wires, no gauge, no length), and temperature margins that are not set or parts without `max_temp_c`. The voltage-drop rule no longer skips AWG 0.
- **New example `flatsat`** (`harness new bench --template flatsat`): a complete bench setup of 23 flight and ground units, 44 interfaces, 8 harnesses and 103 wires, shipped generated with EXAMPLE numbers (the configuration files stay marked as placeholders, the parts are example parts). It has ground equipment (checkout system, ground power supply, RF test equipment), four lanes and links between lanes grouped by `per_zone_pair`. A tour with exercises is in `docs/FLATSAT_EXAMPLE.md`; a test checks it against the project.
- **New example `minimal-satellite`**: seven units without redundancy, between `first-steps` and `small-satellite`, as a small realistic starting point. `harness new --list` now has a name column wide enough for the longest template name (18 characters).
- **New template `design-worksheet.md`** (`harness templates DIR`): a worksheet to plan units, interfaces and the data you do not have yet before opening the tool.
- **Fix: regeneration after a reload** (D-139). A saved project sorts the parts of a harness by ID as text (`S10` before `S2`) but the generator numbered them, so a harness with ten or more shields or segments was reported as *changed* on every generation although nothing had changed. The generator now uses the saved order. A project that has such harnesses shows them as *changed* once on the next generation, and the model hash of such a project changes once; afterwards it is stable. The flatsat example found it.
- **The harness drawing is a wiring diagram** (D-141), after the old wire-by-wire list was found unreadable. Connectors are tables on the left and the right (id, part, gender in words, pin count, the mating box connector, the number and signal of every used pin); the wires between them are curves in their wire colour; each connector pair has a cable block that lists its wires (ID and colour code) with count, gauge and length. Shields, segments, spare pins and the routing sketch follow beneath, and long harnesses continue on further sheets. Wire colours are drawn on a dark outline and also written as IEC 60757 codes, so a greyscale print loses nothing (REQ-OUT-03 reworded; it used to say black and grey only). A wire's colour is data: set by hand, or by the new optional `generation.json` key `wire_colour_by_signal` (for example `{"PWR": "red", "RTN": "black"}`); the tool defines no colours, so an unset wire is grey. - **Harness drawing, correctness** (audit of 2026-10-10): a cable block can no longer run into the title block (it was pushed down by half a header and went past the sheet's room on long harnesses), the routing sketch no longer takes room on every sheet (a harness with a branch point and 8 to 12 leaves came out at one wire per sheet) and is left out when it would take more than half a sheet, a wire in two shields keeps both sleeves (nested, darker inside; the flatsat's W002 drew 12 of its 19), a wire with both ends on one side no longer runs backwards through its block, long pin IDs are shortened instead of overlapping the signal, and the shield and spare-pin lines beneath the drawing are wrapped instead of cut off (the ends come first). - **Ready for the data still to come**: `harness config` (hand-over checklist, range and table validation, ampacity CSV), `config-invalid` rule, `harness import-parts` (approved parts list, you define what the approval values mean), `harness import-lengths` (millimetres, for lengths measured outside the tool); `docs/IMPORTS.md`, `docs/OPEN_DECISIONS.md` (options for D-10 and D-15).
- **KiCad import** (`harness import-netlist`, `docs/KICAD.md`): unit connector pinouts from a KiCad netlist (S-expression or XML) as fixed pins that generation respects. Read correctly on one real KiCad 10.0.6 netlist.
- Ubuntu 22.04 build image and clean-machine test scripts (`packaging/ubuntu/container/`; need Docker, not run here), `README.md`.

## 0.1.0rc2

- **Drawing preview** in the Harness plans tab: the exact sheet the export draws, with next/previous for multi-sheet harnesses.
- **Routing sketch** on the first drawing sheet: connectors and branch points as boxes, segments with lengths (schematic, not to scale).
- **Outline** tab: every unit with its interfaces as a tree that screen readers read item by item; selection follows the diagram.
- **Arrange diagram** (Edit/View menu): units stay in their lanes, ordered to shorten links, one undo step.
- Bottom panel capped at 45% of the window and wider toasts, so the diagram keeps room at large UI scales.
- Multi-drop interfaces (more than two units) are still not generated; they need an engineering rule (see `docs/DECISIONS.md` D-116).

## 0.1.0rc1

First feature-complete version for Ubuntu 22.04 and 24.04 (Windows and RHEL are not targets).

- **Model and files** (M1): human-readable, diffable project folders; atomic saves with backups; recovery mode; schema migrations; project lock; autosave journal.
- **Block diagram editor** (M2): zone lanes, guided and expert modes, connect tool with compatibility reasons, problems and to-do lists, import from CSV/XLSX, light and dark themes, UI scale 100 to 200%, first-run tour.
- **Generation** (M3): harness segmentation, pin allocation with reasons, wiring, wire sizing from configured tables, lengths and mass, stable IDs, regeneration report, independent verifier.
- **Design rule check** (M4): 20 rules with plain-language explanations, waivers with reasons, report, background run.
- **Outputs** (M5): drawings (SVG, PDF), wire lists, pinouts, BOM, mass and length, test tables, labels, system diagrams and matrices, XLSX, WireViz-style YAML, JSON; manifest, stale detection, independent output verifier.
- **Change control** (M6): review, release with gate, baselines, locks, new revisions, diff, change log, revision report.
- **Polish** (M7): accessibility audit and fixes (names for all controls, announced canvas), user guide (F1, offline), rule and configuration reference, soak test, link-label placement, hidden-panel hints, faster integrity checks, Ubuntu `.deb` and `.tar.gz` with install scripts, release checklist tool.

Known open items are listed in `docs/demos/M7.md`. Real derating and EMC values (D-11) and the harness boundary rule (D-10) still need the owner; until then results say so.
