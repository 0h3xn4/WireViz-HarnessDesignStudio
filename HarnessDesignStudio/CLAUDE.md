## Conventions
- `core` must not import `gui`, `cli` or any network module. Offline guarantee is tested.
- All model changes go through commands/transactions; GUI never mutates the model directly.
- Deterministic everywhere: sort by stable IDs, no timestamps in generated data, canonical JSON.
- Never invent standard values (derating, current ratings, mass). Use `PLACEHOLDER` config values and list them for the owner.
- No design data in logs. UI strings in one module.
- The screen says *device*, the files say *unit* (`Unit`, `units`, `logical/units/`, `unit_id`, and the finding texts that reach a written output file); the command line has `--device` and keeps `--unit`; the one exception is the connection list (`system/connections.csv` and `.xlsx`, new in 1.9), whose headings say *device* (owner decision); a wording change on screen must not change a generated file (`python -m tools.output_hashes --check docs/ui/OUTPUT_HASHES_1.2.0.json`).
- Every new dependency: record name, version, licence in `docs/DECISIONS.md`.
- Tests first; every bug fix gets a regression test.
- End each session with: done, tested, next, UX targets met/open.

## UI design rules (UI overhaul, from M1 on; the brief is `docs/ui/UI_OVERHAUL.md`, the plan `docs/ui/UI_OVERHAUL_PLAN.md`)
- **UI only.** Never change computation, core or engine behaviour, project or scenario file formats, CLI commands and flags, or any generated output file; outputs stay byte-identical to the previous release. If a UI improvement seems to need a core change, stop and ask. (This rule belonged to the 1.3.0 overhaul. Version 1.4.0, the AIT feedback, is not UI only: the owner asked for it, see `docs/ait/AIT_FEEDBACK_PLAN.md` and D-160. Its rule instead: **a field added after 1.3.0 is optional and not written while it has its default value** (`SparseEntity.OMIT_WHEN_DEFAULT` in `core/model/base.py`), and an output column or text that depends on it exists only when it is used, so existing projects keep byte-identical files and outputs; the proof is `python -m tools.output_hashes --check docs/ui/OUTPUT_HASHES_1.2.0.json`.)
- **Stay on PySide6, offline.** No third-party Qt theme packages, no network at run time; every font and icon is bundled. New dependencies only with an entry in `docs/DECISIONS.md`.
- **One token source: `gui/theme/tokens.py`.** Colours (`bg.canvas/surface/raised/hover/selected`, `border.subtle/strong/control`, `text.primary/secondary/muted`, `accent`, `status.critical/serious/caution/normal/standby/off`, `diff.added/removed/changed`), type scale (11 caption, 12 small and table, 13 body, 15 section, 18 title, 22 display; weights 400, 500, 600 only), 4 px grid, control height 32 (28 compact), table rows 26, radius 6 for controls and 8 for panels and dialogs, focus ring 2 px accent, shadows only on floating things, motion 120 to 180 ms (0 with reduce motion). Inter for the interface, JetBrains Mono for IDs, pin numbers, part numbers, hashes, paths and logs. The legacy names (`bg`, `surface`, `primary`, `error`) are aliases to retire as screens are rebuilt.
- **The style sheet holds no colour.** `gui/theme/qss.py` names palette roles; `palette.py` maps tokens to roles. A theme switch sets the palette and repolishes visible widgets (hidden ones are unpolished and polish when shown); never `setStyleSheet` with new text to change colours (it costs 300 to 500 ms). A new token that a rule needs gets a palette role in `palette.ROLES`.
- **Contrast.** Every text token reaches 4.5:1 on every surface in both themes, outlines of controls and the focus ring 3:1 (`tests/test_tokens.py`). Colour is never the only carrier of meaning (icon and word too).
- **Never freeze.** Nothing longer than about 50 ms on the GUI thread: workers (`background.JobRunner`, `QThread`, `QProcess`) with progress and cancel, results back by signal; model/view for tables; heavy tabs created lazily; typing-triggered recomputation debounced (about 250 ms). Measure with `python -m tools.ui_perf` and `python -m tools.bench_gui` (baseline in `docs/ui/PERF_BASELINE.md`).
- **Modal dialogs only** for destructive confirmations and multi-step wizards; everything else is inline or in the inspector; success is a non-modal toast; every list and table has an empty state with the primary action.
- **Accessibility.** Keyboard reach and visible focus everywhere, tooltips on every icon-only button, OS scaling plus the UI-scale setting.
- **Screenshots.** Re-run `python -m tools.ui_screenshots` at the end of every milestone and mention noteworthy differences; the "before" set is in `docs/ui/screenshots/before/`. The set of release 1.3.0 is `docs/ui/screenshots/after/` and the comparison `docs/ui/BEFORE_AFTER.md`; the tool runs each theme and part in a process of its own (two themes in one process crash Qt's offscreen platform).
- **Settings.** Every control of the Settings page is a view of a menu action (`gui/settings_page.py`): the window stores and applies the value, and the page follows when a menu or Ctrl+K changes it; a new setting is a checkable action first, then a control, with a test that a second window on the same settings file restores it.
- **Keyboard.** A tab widget whose bar is hidden must not be a Tab stop (`SlotTabs._sync_bar`; the Tab key would stop at it). `tests/test_ui_final.py` walks every area in both themes: no Qt warning, accessible names, tooltips on icon-only buttons, a Tab walk that comes back to where it started, visible focus. A new area, tab or page goes into its `_views()`.
- **Outputs.** A UI change must leave every written file alone: `python -m tools.output_hashes --check docs/ui/OUTPUT_HASHES_1.2.0.json` (and `tests/test_output_hashes.py`) compares all files of the four examples with release 1.2.0, apart from the version stamp. A change of the tool version is the one thing that changes bytes (regenerate with `tools.build_examples`, `tools.gen_output_goldens`, the fixtures' `tool_version`, and the quoted hashes in the documents).
